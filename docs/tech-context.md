# Технический контекст проекта

> **Как использовать.** Положите этот файл в репозиторий как `docs/tech-context.md`.
> Конституция проекта ссылается на него и требует читать его при каждом
> `/speckit.plan`, поэтому вставлять его вручную не нужно. В `/speckit.plan`
> передаётся только часть B из файла самой фичи.
>
> В `/speckit.specify` этот файл не используется: спецификация описывает
> «что и зачем», без технологий.
>
> Файл живой: выбор, сделанный в плане фичи, и результаты проверок записываются сюда.
>
> Пометка **[проверить]** означает, что решение не проверено на этом ноутбуке
> и должно быть подтверждено до начала работы над зависящей от него фичей.

## Раскладка в репозитории

```
docs/
  tech-context.md        ← этот файл
  field-catalog.md       ← каталог полей
  features/              ← файлы фич 01–12
.specify/
  memory/constitution.md ← создаёт /speckit.constitution
```

Договоры, эталон, результаты и веса моделей лежат в папке данных вне репозитория.

## Оборудование

| Параметр | Значение |
|---|---|
| Машина | MacBook Pro, Apple M3 Pro |
| Память | 36 ГБ, общая для процессора и графики |
| Диск | около 128 ГБ свободно |
| Сеть во время обработки | не используется (принцип I конституции) |

Следствия:

- Видеокарты NVIDIA нет. Всё, что требует CUDA, не подходит.
- Языковая модель, модель поиска и реранкер делят одни и те же 36 ГБ.
- Веса моделей займут заметную часть диска: закладывайте 25–30 ГБ.
- Код пишется с помощью Claude Code. Это не нарушает принцип I, пока в запросы
  к нему не попадают тексты реальных договоров: отладка ведётся на синтетических
  примерах.

## Общие решения

| Часть | Выбор | Статус |
|---|---|---|
| Язык | Python 3.11 или новее | решено |
| Управление окружением | `uv` | решено |
| Запуск конвейера и замеров | одна команда командной строки с подкомандами | решено |
| Экран для аналитика | локальная веб-страница с готовым чат-компонентом | библиотека выбирается в плане фичи 12 |
| Хранилище | PostgreSQL с расширением pgvector | решено |
| Исходные файлы | папка на диске; в базе только пути и контрольные суммы | решено |
| Входной формат | только PDF с извлекаемым текстом | решено |
| Чтение PDF | библиотека извлечения текста с координатами | выбирается в плане фичи 03 |
| Языковая модель (фичи 05, 09, 10, 11) | Qwen3.6-27B, сжатая до 4 бит | решено, скорость **[проверить]** |
| Запуск языковой модели | локальный сервер с OpenAI-совместимым интерфейсом | способ запуска **[проверить]** |
| Ответы модели по форме | Instructor | решено |
| Русская морфология | приведение слов к словарной форме (`pymorphy3`) | решено |
| Поиск по смыслу | BGE-M3; для сравнения FRIDA | решено |
| Реранкер | BGE Reranker v2-m3, отключаемый | решено |
| Оценка ответов моделью-судьёй | не используется | решено |

Что не входит в первый этап и не должно появляться в планах: распознавание сканов
(ИИ-ридеры, классический OCR), файлы Word, связи между договорами, казахский язык,
учётные записи и доступ по сети.

Пояснения к решениям, которые не очевидны:

- **OpenAI-совместимый интерфейс.** Код обращается к модели по одному адресу
  и не знает, чем она запущена. Способ запуска или саму модель можно сменить без
  изменения кода и сравнить варианты в замерах.
- **Способ запуска модели.** Кандидаты для Apple Silicon: сервер на MLX либо сервер
  на llama.cpp (в том числе через Ollama или LM Studio). Выбор делается по замеру
  скорости на одной странице договора.
- **Библиотека чтения PDF.** Нужны текст в порядке чтения и координаты каждой строки
  на странице: по ним веб-экран подсвечивает цитату. При выборе учесть лицензию:
  у части библиотек она требует открывать исходный код при распространении.
- **Поиск по словам в PostgreSQL.** Встроенный полнотекстовый поиск имеет русскую
  конфигурацию, но его ранжирование — не BM25. Для 50 договоров допустимы оба
  варианта: встроенный поиск по тексту, заранее приведённому к словарным формам,
  либо BM25 в памяти процесса. Выбор делается в плане фичи 07 и проверяется замером
  в фиче 08.
- **FRIDA** принимает не более 512 фрагментов слов на отрывок и требует приставок
  `search_query:` и `search_document:`. Происхождение модели (Сбер) нужно согласовать
  с юристами до использования за пределами PoC.
- **Веб-экран.** Кандидаты: Gradio, Chainlit, Streamlit. Требования к выбору: готовое
  окно чата, таблица, показ страницы PDF с подсветкой, работа без сети (без загрузки
  шрифтов и скриптов из интернета), отключаемая телеметрия.

## Договорённости между этапами

- Этап получает идентификаторы документов и читает из хранилища результат
  предыдущего этапа. На выходе — записи в хранилище и обновлённый `stage_status`.
- Состояния этапа для документа: `pending`, `done`, `needs_review`, `failed`.
  У состояний `needs_review` и `failed` обязательно указана причина.
- Каждый запуск этапа создаёт запись `run`. Результаты ссылаются на неё.
- Повторный запуск этапа для документа заменяет прежний результат этого этапа.
  Результаты следующих этапов при этом помечаются как устаревшие.
- Идентификатор пункта строится из идентификатора документа, части документа
  и номера пункта, например `D-0001/5.2` или `D-0001/П1/2` для пункта приложения.
  Он используется в цитатах, эталоне и ссылках на источник.

## Что проверить в первый день

1. **Языковая модель.** Запустить сжатую Qwen3.6-27B, измерить скорость на одной
   странице договора и занятую память. Все оценки скорости в исследовании были
   предположением, не замером.
2. **Качество текста в PDF.** На трёх договорах убедиться, что извлечённый текст
   читается, а номера пунктов (5.2, 5.2.1) и заголовки разделов сохранились.
   Отдельно проверить, нет ли среди файлов сканов со встроенным текстом.
3. **Память.** Проверить, что языковая модель, модель поиска и реранкер помещаются
   в 36 ГБ одновременно, либо заложить их поочерёдную загрузку.

## Допущения, принятые без подтверждения

Если любое из них неверно, скажите до начала работы над зависящими фичами.

| Допущение | На что влияет |
|---|---|
| Все договоры — PDF, из которых извлекается текст; сканов нет | Фича 03; при появлении сканов нужен отдельный этап распознавания |
| Договоры имеют нумерованные пункты и стандартную структуру | Фича 04 строится на правилах, без модели |
| Таблицы в приложениях читаются и ищутся, но построчно не извлекаются | Фичи 03, 05; ответ даст первый прогон чтения |
| Объём одного договора — десятки страниц | Время прогона, размер отрывков |
| У договора две стороны: генеральный подрядчик и субподрядчик | Каталог полей, фичи 05, 06, 10 |
