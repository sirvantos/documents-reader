# Фича 05. Извлечение полей по формам с цитатой

## Часть A. Описание для /speckit.specify

### Суть

Для каждого договора система заполняет поля из каталога полей. Поля разбиты
на шесть групп, и каждая группа заполняется отдельно. Для каждого значения
сохраняется дословная цитата из договора и пункт, где она находится. Программа
проверяет, что цитата действительно есть в тексте и что значение взято из неё.
Значение без подтверждённой цитаты в таблицу не попадает. Если данных в договоре
нет, поле остаётся пустым с отметкой «не найдено».

### Зачем

Таблица полей отвечает на вопросы, на которые поиск по тексту ответить не может:
сколько договоров, на какую сумму, какие истекают в этом году. Языковая модель
иногда выдаёт правдоподобное, но неверное значение; обязательная цитата и её
программная проверка превращают незаметную ошибку в заметную и дают аналитику
место в договоре, по которому значение можно проверить за секунды.

### Пользователь

Один аналитик. Он запускает извлечение из командной строки и просматривает
результат в выгруженной таблице.

### Сценарии

**Сценарий 1. Заполнить поля договора (приоритет P1)**

Проверяется отдельно: извлечь поля одного договора и сверить их с исходным файлом.

Критерии приёмки:

1. **Дано** договор разобран на пункты. **Когда** аналитик запускает извлечение.
   **Тогда** для каждого поля каталога сохранён один из результатов: значение
   с цитатой, «не найдено», «отклонено» или «ошибка».
2. **Дано** значение найдено. **Когда** аналитик смотрит результат. **Тогда**
   он видит значение как в договоре, приведённое значение, цитату и идентификатор
   пункта.
3. **Дано** в договоре дата записана как «1 марта 2025 г.». **Когда** выполняется
   извлечение. **Тогда** сохранены и запись из договора, и приведённая дата.

**Сценарий 2. Проверка цитаты (приоритет P1)**

Проверяется отдельно: подать на проверку подготовленные ответы с верными
и неверными цитатами.

Критерии приёмки:

1. **Дано** цитата дословно присутствует в тексте договора. **Когда** выполняется
   проверка. **Тогда** значение принято, а цитате сопоставлено место в тексте.
2. **Дано** цитаты нет в тексте договора. **Когда** выполняется проверка.
   **Тогда** значение получает результат «отклонено» с причиной «цитата
   не найдена» и не попадает в таблицу как найденное.
3. **Дано** цитата есть, но значение в ней отсутствует (для дат, сумм, номеров).
   **Когда** выполняется проверка. **Тогда** результат «отклонено» с причиной
   «значение не подтверждено цитатой».
4. **Дано** цитата отличается от текста только пробелами, переносами или видом
   кавычек. **Когда** выполняется проверка. **Тогда** цитата считается найденной.

**Сценарий 3. «Не найдено» (приоритет P1)**

Проверяется отдельно: извлечь поля из договора, в котором заведомо нет части
сведений.

Критерии приёмки:

1. **Дано** в договоре нет сведений о предоплате. **Когда** выполняется
   извлечение. **Тогда** поле доли предоплаты имеет результат «не найдено»,
   а не значение по умолчанию.
2. **Дано** срок записан формулой («в течение 30 дней с даты оплаты»). **Когда**
   выполняется извлечение. **Тогда** текстовое поле заполнено, а парное поле
   с календарной датой имеет результат «не найдено».

**Сценарий 4. Подбор нужных частей договора (приоритет P2)**

Каждая группа полей читает только те части договора, где обычно находятся её
сведения; если там ничего не найдено, читается договор целиком.

Проверяется отдельно: сравнить результат группы при чтении выбранных частей
и всего договора.

Критерии приёмки:

1. **Дано** группа «Стороны». **Когда** выполняется извлечение. **Тогда** модель
   получает преамбулу и блок реквизитов и подписей.
2. **Дано** обязательное поле не найдено в выбранных частях. **Когда** выполняется
   извлечение. **Тогда** система повторяет попытку по всему тексту договора.
3. **Дано** извлечение завершено. **Когда** аналитик смотрит сведения о запуске.
   **Тогда** видно, какие части договора были показаны модели для каждой группы.

**Сценарий 5. Перезапуск части работы (приоритет P2)**

Проверяется отдельно: перезапустить одну группу для одного договора.

Критерии приёмки:

1. **Дано** извлечение выполнено. **Когда** аналитик перезапускает одну группу
   для одного договора. **Тогда** обновляются только поля этой группы этого
   договора.
2. **Дано** извлечение прервано. **Когда** аналитик запускает его снова.
   **Тогда** уже обработанные договоры не обрабатываются повторно.

**Сценарий 6. Выгрузка таблицы (приоритет P3)**

Проверяется отдельно: выгрузить таблицу после извлечения.

Критерии приёмки:

1. **Дано** извлечение выполнено. **Когда** аналитик выгружает таблицу. **Тогда**
   он получает файл: строка на договор, столбец на поле, плюс подробный вид
   со значением, цитатой, пунктом и результатом по каждому полю.

### Особые случаи

- Одно и то же сведение встречается в договоре несколько раз с разными значениями
  (сумма в тексте и в приложении): сохраняются все найденные варианты, результат
  помечается как «противоречие».
- Значение находится в таблице приложения.
- Поле-список (перечень приложений) имеет несколько значений, у каждого своя
  цитата.
- Договор не помещается в один запрос к модели: читается по частям, результаты
  объединяются.
- Модель вернула ответ не по форме: запрос повторяется ограниченное число раз,
  затем результат «ошибка».
- Модель вернула значение для поля, которого нет в каталоге: оно отбрасывается.
- Сторон не две или их роли не определяются: поля сторон получают результат
  «не найдено», а документ — причину «состав сторон не соответствует допущению».
- Текст договора содержит указания, обращённые к читателю («в ответе укажите…»):
  они воспринимаются как текст договора, а не как указания системе.
- У договора состояние чтения или разбора «требует просмотра»: извлечение
  выполняется, а результат помечается как полученный по сомнительному тексту.
- Документ не имеет текста: извлечение не запускается.

### Требования

- **FR-001.** Система должна заполнять поля строго по каталогу полей, группами.
- **FR-002.** Система должна сохранять для каждого поля ровно один результат:
  «найдено», «не найдено», «отклонено», «противоречие», «ошибка».
- **FR-003.** Система должна сохранять для найденного значения запись из договора,
  приведённое значение, дословную цитату и идентификатор пункта.
- **FR-004.** Система должна программно проверять присутствие цитаты в тексте
  договора и, для дат, сумм, чисел и идентификаторов, присутствие значения
  в цитате.
- **FR-005.** Система не должна сохранять как найденное значение без подтверждённой
  цитаты.
- **FR-006.** Система должна оставлять поле пустым с результатом «не найдено»,
  когда сведений нет, и не подставлять значения по умолчанию.
- **FR-007.** Система должна заполнять парные поля (текст и число или дата)
  независимо: числовое поле заполняется, только если значение однозначно.
- **FR-008.** Система должна сохранять все варианты при противоречии.
- **FR-009.** Система должна позволять запускать извлечение для одного договора,
  одной группы или одного поля, не затрагивая остальное.
- **FR-010.** Система должна сохранять, какие части договора были показаны модели,
  и сведения о запуске: модель, версия подсказки, настройки.
- **FR-011.** Система должна выгружать таблицу полей в файл.
- **FR-012.** Извлечение должно выполняться локально, без обращения к сети.

### Сущности

- **Значение поля.** Договор, поле, результат, запись из договора, приведённое
  значение, цитата, пункт, место цитаты в тексте, запуск.
- **Вариант значения.** Дополнительные значения при противоречии и элементы
  поля-списка.
- **Группа полей.** Набор полей каталога, заполняемых одним обращением к модели.

### Критерии успеха

- **SC-001.** 100% значений с результатом «найдено» имеют цитату, присутствующую
  в тексте договора.
- **SC-002.** Доля исхода «верно» по полям, которые сравниваются с эталоном
  автоматически, — не менее 90%. Целевой ориентир; уточняется после первого замера.
- **SC-003.** Доля исхода «придумано» — не более 2%. Целевой ориентир.
- **SC-004.** Извлечение всех полей из 50 договоров завершается за одну ночь
  (не более 8 часов). Целевой ориентир; скорость модели на ноутбуке не измерена.
- **SC-005.** После каждого запуска результат сравнения с эталоном записан
  в таблицу результатов.

### Вне рамок

- Проверки значений правилами и итоговые статусы (фича 06).
- Исправление значений аналитиком (фичи 06 и 12).
- Построчное извлечение таблиц приложений.
- Поля, которых нет в каталоге.
- Юридическая оценка условий.

### Допущения

- У договора две стороны: генеральный подрядчик и субподрядчик.
- Сведения каждой группы обычно находятся в предсказуемых частях договора.
- Одна языковая модель обслуживает все группы.

### Минимальная версия для сквозного прототипа

Одна группа из шести полей прототипа (см. каталог), модель получает весь текст
договора, проверка цитаты из сценария 2. Подбор частей, противоречия, перезапуск
по группам и выгрузка — позже.

## Часть B. Технические заметки для /speckit.plan

- **Формы.** Одна схема на группу полей (от 3 до 10 полей). Для каждого поля:
  значение как в тексте, цитата, признак «не найдено». Приведение значения
  выполняет код, а не модель.
- **Строгий режим вывода.** В одном исследовании извлечения строгий режим снижал
  долю пригодных ответов. Начать с проверки формы на стороне кода и повторов,
  затем сравнить со строгим режимом в замере.
- **Повторы:** не более двух на группу; после этого результат «ошибка».
- **Случайность:** температура 0; версия подсказки записывается в запуск.
- **Проверка цитаты.** Цитата и текст приводятся общим модулем (пробелы, дефисы,
  кавычки, «ё»), затем ищется точное вхождение в очищенный текст документа. Место
  вхождения даёт пункт и страницу; идентификатор пункта, названный моделью,
  используется только как подсказка при нескольких вхождениях.
- **Подбор частей.** По ключевым словам в заголовках разделов из фичи 04
  (например, «цена», «стоимость», «порядок расчётов» для группы «Деньги»), плюс
  преамбула и реквизиты для групп 1 и 2. Список слов хранить в настройках.
- **Длинные договоры.** Если текст выбранных частей превышает заданный размер,
  делить по разделам и объединять результаты; расхождения дают «противоречие».
- **Память.** Во время извлечения нужна только языковая модель.
- **Таблица хранилища:** `field_value` и таблица вариантов.
- **Команды** (ориентир): `extract [идентификатор…] [--group G] [--field F]`,
  `fields export`, `fields show <идентификатор>`.
- **Тесты.** Проверка цитаты и приведение значений тестируются без модели
  на подготовленных ответах. Для сквозных тестов — синтетические договоры.
