## Часть A. Описание для /speckit.specify

### Суть

Для каждого договора из реестра система получает текст каждой страницы в порядке
чтения и запоминает, где на странице находится каждая строка. Текст очищается
от повторяющихся колонтитулов и переносов слов. Каждая страница проходит проверки
качества; страница, с которой что-то не так, получает флаг и причину. Аналитик видит
отчёт: сколько страниц прочитано, сколько помечено и почему.

### Зачем

Всё остальное строится на этом тексте: разбор пунктов, извлечение полей, поиск
и цитаты. Ошибка здесь незаметно портит все следующие этапы. Положение строк
на странице нужно, чтобы позже показать аналитику цитату прямо в исходном файле.
Проверки качества нужны потому, что допущение «во всех файлах есть хороший текст»
ничем не подтверждено: текст в PDF может оказаться результатом распознавания
сканером или набором нечитаемых знаков.

### Пользователь

Один аналитик. Он запускает чтение из командной строки и читает отчёт.

### Сценарии

**Сценарий 1. Прочитать договор (приоритет P1)**

Аналитик запускает чтение для одного договора или для всех непрочитанных и получает
текст по страницам.

Проверяется отдельно: прочитать один договор и сравнить текст страницы с исходным
файлом.

Критерии приёмки:

1. **Дано** договор с готовым текстом. **Когда** аналитик запускает чтение.
   **Тогда** для каждой страницы сохранён текст в том порядке, в каком его читает
   человек, и для каждой строки известно её положение на странице.
2. **Дано** договор прочитан. **Когда** аналитик запрашивает текст страницы.
   **Тогда** он видит текст этой страницы и её флаги.
3. **Дано** договор уже прочитан. **Когда** аналитик запускает чтение повторно.
   **Тогда** результат заменяется, а не дублируется, и совпадает с прежним.

**Сценарий 2. Проверки качества страницы (приоритет P1)**

Каждая страница проверяется, и сомнительные страницы помечаются.

Проверяется отдельно: прочитать набор подготовленных файлов с известными дефектами.

Критерии приёмки:

1. **Дано** страница вида «скан» без текста. **Когда** выполняется чтение.
   **Тогда** страница не читается, получает флаг «скан, не прочитана», а остальные
   страницы документа обрабатываются.
2. **Дано** страница вида «скан со встроенным текстом». **Когда** выполняется
   чтение. **Тогда** текст сохраняется, а страница получает флаг «текст получен
   распознаванием».
3. **Дано** страница, текст которой состоит из нечитаемых знаков. **Когда**
   выполняется чтение. **Тогда** страница получает флаг «текст не читается».
4. **Дано** страница с несколькими казахскими буквами. **Когда** выполняется
   чтение. **Тогда** страница получает флаг «возможно, не русский текст».
5. **Дано** страница без текста и без изображения. **Когда** выполняется чтение.
   **Тогда** страница получает флаг «пустая», и это не считается ошибкой.
6. **Дано** в документе есть хотя бы одна страница с флагом, кроме «пустая».
   **Когда** чтение завершено. **Тогда** состояние этапа для документа — «требует
   просмотра» с перечнем причин; иначе — «готово».

**Сценарий 3. Очистка текста (приоритет P2)**

Колонтитулы и номера страниц убираются из основного текста, слова с переносом
склеиваются, а положение исходных строк сохраняется.

Проверяется отдельно: прочитать договор с колонтитулом на каждой странице
и с переносами слов.

Критерии приёмки:

1. **Дано** одинаковая строка повторяется в одном и том же месте на большинстве
   страниц. **Когда** выполняется чтение. **Тогда** она не входит в основной текст,
   но сохранена отдельно.
2. **Дано** слово разорвано переносом в конце строки. **Когда** выполняется чтение.
   **Тогда** в очищенном тексте слово записано слитно.
3. **Дано** очищенный текст. **Когда** система ищет в нём любую фразу. **Тогда**
   для найденной фразы можно определить страницу и место на странице.
4. **Дано** предложение продолжается на следующей странице. **Когда** выполняется
   чтение. **Тогда** в тексте документа оно не разорвано колонтитулом.

**Сценарий 4. Таблицы (приоритет P2)**

Страницы с таблицами распознаются, таблица помечается как таблица и сохраняется
построчно.

Проверяется отдельно: прочитать договор с приложением в виде таблицы.

Критерии приёмки:

1. **Дано** страница с таблицей. **Когда** выполняется чтение. **Тогда** страница
   отмечена как содержащая таблицу, а текст ячеек одной строки таблицы стоит рядом.
2. **Дано** чтение набора завершено. **Когда** аналитик смотрит отчёт. **Тогда**
   он видит число страниц с таблицами по каждому документу.

**Сценарий 5. Отчёт о чтении (приоритет P3)**

Аналитик получает сводку по набору.

Проверяется отдельно: прочитать несколько договоров и запросить отчёт.

Критерии приёмки:

1. **Дано** чтение завершено. **Когда** аналитик запрашивает отчёт. **Тогда**
   он видит по каждому документу число прочитанных страниц, число страниц с каждым
   флагом и число страниц с таблицами, а также итог по набору.
2. **Дано** отчёт. **Когда** аналитик выгружает его. **Тогда** он получает файл
   для табличного редактора.

### Особые случаи

- Страница повёрнута: текст читается в правильном порядке либо страница получает
  флаг.
- Текст в две колонки: колонки читаются по очереди, а не построчно через обе.
  Если порядок определить нельзя, страница получает флаг.
- Текст внутри изображений (печати, штампы, подписи) не читается и не считается
  ошибкой.
- Сноски и текст мелким шрифтом внизу страницы сохраняются.
- Один и тот же знак продублирован из-за имитации жирного шрифта: дубли убираются.
- Неразрывные пробелы, разные виды дефисов и кавычек приводятся к одному виду
  в очищенном тексте.
- Дефис в составных словах и номерах («123/45-У») не считается переносом.
- Одна казахская буква на странице (например, в фамилии) флага не вызывает.
- Документ целиком состоит из страниц-сканов, ещё не распознанных (фича 13):
  состояние «требует просмотра», текст пуст, следующие этапы для него не запускаются.
- Чтение одного документа завершилось ошибкой: остальные документы обрабатываются,
  ошибка записана.

### Требования

- **FR-001.** Система должна сохранять для каждой страницы текст в порядке чтения.
- **FR-002.** Система должна сохранять положение каждой строки текста на странице.
- **FR-003.** Система должна формировать очищенный текст документа и позволять
  по любому его фрагменту определить страницу и место на странице.
- **FR-004.** Система должна убирать из основного текста повторяющиеся колонтитулы
  и номера страниц, сохраняя их отдельно.
- **FR-005.** Система должна склеивать слова, разорванные переносом.
- **FR-006.** Система должна присваивать странице флаги: «скан, не прочитана»,
  «текст получен распознаванием», «текст не читается», «возможно, не русский
  текст», «пустая», «порядок чтения не определён».
- **FR-007.** Система должна отмечать страницы с таблицами и сохранять таблицу
  построчно.
- **FR-008.** Система должна выставлять состояние этапа для документа и причины.
- **FR-009.** Система должна читать один документ, выбранные документы или все
  непрочитанные.
- **FR-010.** Чтение не должно обращаться к языковой модели и к сети; при
  одинаковых входных данных оно всегда даёт одинаковый результат.
- **FR-011.** Система должна выдавать отчёт о чтении по документам и по набору.

### Сущности

- **Текст страницы.** Страница, строки с положением, флаги, признак таблицы.
- **Очищенный текст документа.** Сплошной текст и соответствие между его местами
  и строками на страницах.
- **Вынесенные элементы.** Колонтитулы и номера страниц, убранные из текста.

### Критерии успеха

- **SC-001.** Не менее 99% контрольных строк эталона (фича 02) найдены в очищенном
  тексте дословно.
- **SC-002.** 100% страниц набора либо прочитаны, либо имеют флаг с причиной.
- **SC-003.** Для 100% фрагментов очищенного текста определяется страница.
- **SC-004.** Чтение 50 договоров занимает не более 10 минут.
- **SC-005.** Повторное чтение даёт тот же текст.
- **SC-006.** На 10 страницах, проверенных вручную, колонтитулы отсутствуют
  в основном тексте, а ни одна строка основного текста не потеряна.

### Вне рамок

- Распознавание сканов и изображений (фича 13, конституция 3.0.0): эта фича пропускает скан с флагом,
  фича 13 даёт для него строки, и чтение берёт их.
- Разбор на разделы и пункты (фича 04).
- Понимание содержимого таблиц и извлечение их строк как данных.
- Исправление ошибок в тексте, полученном распознаванием.
- Перевод и обработка казахского текста.

### Допущения

- ~~В большинстве файлов текст создан текстовым редактором, а не сканером.~~ Неверно

### Минимальная версия для сквозного прототипа

Сценарий 1 и два флага из сценария 2: «скан, не прочитана» и «пустая». Положение
строк сохраняется сразу, потому что добавлять его позже дорого. Очистка, таблицы
и отчёт — позже.

## Часть B. Технические заметки для /speckit.plan

- **Выбор библиотеки.** Нужны: текст в порядке чтения, прямоугольник каждой строки,
  сведения об изображениях на странице, поиск таблиц. Сравнить два-три кандидата
  на трёх договорах и записать выбор в `docs/tech-context.md`. Учесть лицензию.
- **Два слоя текста.** Хранить строки страницы как есть (с прямоугольниками)
  и отдельно очищенный текст документа с таблицей соответствия «диапазон символов
  → страница, строка». Цитаты проверяются по очищенному тексту, подсветка строится
  по строкам.
- **Колонтитулы.** Строка считается колонтитулом, если после замены цифр на метку
  она повторяется в верхней или нижней полосе страницы более чем на половине
  страниц. Пороговые значения подобрать на реальных договорах.
- **Нечитаемый текст.** Признаки: низкая доля букв кириллицы и цифр среди всех
  знаков, много знаков замены, много «слов» без гласных. Пороги подобрать
  на подготовленных примерах.
- **Казахские буквы.** Проверять по кодам знаков кириллицы, а не по внешнему виду:
  казахская «І» отличается от латинской «I» кодом. Порог — несколько таких букв
  на странице.
- **Приведение знаков.** Те же правила приведения пробелов, дефисов, кавычек
  и «ё», что в общем модуле из фичи 02; иначе проверка цитат будет давать ложные
  несовпадения.
- **Таблицы хранилища:** `page_text` и таблица очищенного текста документа.
- **Команды** (ориентир): `read [идентификатор…]`, `read --all`, `read report`,
  `text <идентификатор> [--page N]`.
- **Тесты.** Синтетические PDF: обычный, с колонтитулами, с переносами, с таблицей,
  в две колонки, с повёрнутой страницей, с нечитаемым текстовым слоем, со страницей
  из одного изображения.
