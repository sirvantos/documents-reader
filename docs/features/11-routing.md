# Фича 11. Выбор маршрута и маршрут «таблица, затем текст»

## Часть A. Описание для /speckit.specify

### Суть

Аналитик задаёт вопрос одной командой, не выбирая, куда его направить. Система
определяет маршрут: ответ по таблице, ответ по тексту или оба по очереди.
В третьем случае таблица сначала отбирает договоры, а затем поиск по тексту идёт
только среди них. Для маршрута по тексту система выделяет из вопроса условия
отбора — номер договора, сторону, период. Выбранный маршрут показан в ответе,
и аналитик может задать его вручную.

### Зачем

Вопрос на подсчёт, отправленный в поиск по тексту, даёт уверенный неверный ответ;
вопрос о содержании пункта, отправленный в таблицу, не даёт ничего. Аналитик
не должен помнить это различие для каждого вопроса. Многие настоящие вопросы
смешанные: «что сказано о неустойке в договорах с субподрядчиком X за 2025 год» —
отбор по таблице, содержание из текста.

### Пользователь

Один аналитик. Он задаёт вопросы из командной строки, позже — через веб-экран.

### Сценарии

**Сценарий 1. Выбор маршрута (приоритет P1)**

Проверяется отдельно: задать по одному вопросу каждого вида.

Критерии приёмки:

1. **Дано** вопрос на подсчёт, сумму или перечень. **Когда** аналитик задаёт его.
   **Тогда** вопрос направлен в таблицу, и это указано в ответе.
2. **Дано** вопрос о содержании условий. **Когда** аналитик задаёт его. **Тогда**
   вопрос направлен в поиск по тексту, и это указано в ответе.
3. **Дано** вопрос о содержании условий в договорах, отобранных по признаку.
   **Когда** аналитик задаёт его. **Тогда** выбран маршрут «таблица, затем текст».
4. **Дано** маршрут определить не удаётся. **Когда** аналитик задаёт вопрос.
   **Тогда** система использует маршрут по тексту и сообщает, что маршрут выбран
   по умолчанию.

**Сценарий 2. Маршрут «таблица, затем текст» (приоритет P1)**

Проверяется отдельно: задать смешанный вопрос по набору с заполненной таблицей.

Критерии приёмки:

1. **Дано** смешанный вопрос. **Когда** он выполняется. **Тогда** сначала таблица
   отбирает договоры, затем поиск по тексту идёт только по ним, и ответ содержит
   цитаты только из них.
2. **Дано** отбор выполнен. **Когда** аналитик читает ответ. **Тогда** он видит
   применённое условие отбора и число отобранных договоров.
3. **Дано** отбору не соответствует ни один договор. **Когда** вопрос выполняется.
   **Тогда** система сообщает об этом и не ищет по всему набору.
4. **Дано** отобрано очень много договоров. **Когда** вопрос выполняется.
   **Тогда** ответ строится по найденным отрывкам и прямо говорит, что это
   примеры, а не полный обзор всех отобранных договоров.

**Сценарий 3. Условия отбора из вопроса (приоритет P2)**

Проверяется отдельно: задать вопрос по тексту с упоминанием номера договора.

Критерии приёмки:

1. **Дано** в вопросе назван номер договора. **Когда** выполняется поиск
   по тексту. **Тогда** поиск ограничен этим договором.
2. **Дано** в вопросе названа сторона или период. **Когда** выполняется поиск.
   **Тогда** применён соответствующий фильтр, и он показан в ответе.
3. **Дано** названный в вопросе номер договора не найден в таблице. **Когда**
   вопрос выполняется. **Тогда** система сообщает об этом и не снимает условие
   сама.

**Сценарий 4. Ручной выбор маршрута (приоритет P2)**

Проверяется отдельно: задать один вопрос с принудительным маршрутом.

Критерии приёмки:

1. **Дано** аналитик указал маршрут. **Когда** вопрос выполняется. **Тогда**
   используется указанный маршрут, а автоматический выбор не выполняется.
2. **Дано** ответ получен по автоматически выбранному маршруту. **Когда** аналитик
   повторяет вопрос с другим маршрутом. **Тогда** он получает второй ответ, и оба
   сохранены.

**Сценарий 5. Замер выбора маршрута (приоритет P3)**

Проверяется отдельно: прогнать эталонные вопросы, у которых указан вид.

Критерии приёмки:

1. **Дано** у эталонных вопросов указан вид (таблица, текст, оба). **Когда**
   аналитик запускает прогон. **Тогда** он получает долю вопросов с верно
   выбранным маршрутом и список ошибок.
2. **Дано** прогон выполнен. **Когда** результат записан. **Тогда** в таблице
   результатов есть запись с меткой.

### Особые случаи

- Вопрос на подсчёт по свойству, которого нет в каталоге полей: система сообщает,
  что точно посчитать не может, и по желанию показывает несколько найденных
  примеров из текста, явно названных примерами, без числа.
- Вопрос содержит и подсчёт, и вопрос о содержании: выполняются по очереди, ответы
  показаны раздельно.
- Вопрос не о договорах: отказ, как в фиче 09.
- Отбор опирается на поле с непроверенными значениями: в ответе указано, сколько
  договоров могли не попасть в отбор.
- Слово-признак подсчёта употреблено в другом смысле («сколько дней даётся
  на оплату» — вопрос по тексту, не на подсчёт).
- Вопрос ссылается на предыдущий («а в других договорах?»): каждый вопрос
  обрабатывается отдельно; система просит задать вопрос полностью.

### Требования

- **FR-001.** Система должна принимать вопрос одной командой и определять маршрут:
  таблица, текст, таблица и затем текст.
- **FR-002.** Система должна показывать в ответе выбранный маршрут и то, выбран
  ли он автоматически, по умолчанию или вручную.
- **FR-003.** Система должна позволять задать маршрут вручную.
- **FR-004.** На маршруте «таблица, затем текст» система должна ограничивать поиск
  по тексту договорами, отобранными таблицей.
- **FR-005.** Система должна выделять из вопроса условия отбора по полям-фильтрам
  и показывать их в ответе.
- **FR-006.** Система не должна ослаблять или снимать условие отбора
  самостоятельно.
- **FR-007.** Система никогда не должна выдавать как результат подсчёта число,
  полученное пересчётом найденных отрывков.
- **FR-008.** Система должна измерять долю верно выбранных маршрутов на эталонных
  вопросах.
- **FR-009.** Система должна ограничивать число шагов и время на один вопрос.
- **FR-010.** Система должна сохранять вопрос, выбранный маршрут, условия отбора
  и ответ.

### Сущности

- **Решение о маршруте.** Вопрос, маршрут, способ выбора, условия отбора.
- **Составной ответ.** Результат отбора и ответ по тексту.

### Критерии успеха

- **SC-001.** Маршрут выбран верно не менее чем для 90% эталонных вопросов.
  Целевой ориентир; уточняется после первого замера.
- **SC-002.** Ноль ответов на эталонные вопросы, в которых число получено
  пересчётом найденных отрывков.
- **SC-003.** Не менее 75% эталонных вопросов вида «оба» получают верный ответ.
  Целевой ориентир.
- **SC-004.** 100% ответов показывают выбранный маршрут и применённые условия.
- **SC-005.** Выбор маршрута добавляет к времени ответа не более 10 секунд.
  Целевой ориентир.

### Вне рамок

- Поиск в несколько шагов с переформулировкой вопроса.
- Диалог с памятью о предыдущих вопросах.
- Разбиение сложного вопроса более чем на две части.
- Сводки по всем отобранным договорам сразу.

### Допущения

- Маршруты по таблице и по тексту уже работают (фичи 09 и 10).
- Большинство вопросов однозначно относится к одному маршруту.

### Минимальная версия для сквозного прототипа

В прототип не входит. Первая рабочая версия: выбор между таблицей и текстом
по списку слов-признаков и ручной выбор маршрута.

## Часть B. Технические заметки для /speckit.plan

- **Два уровня выбора.** Сначала дешёвые правила по словам-признакам («сколько
  договоров», «общая сумма», «перечисли все», «самый крупный»); если правила
  не дали уверенного ответа — языковая модель с формой: маршрут и условия отбора.
- **Условия отбора** используют ту же форму и ту же проверку допустимых полей, что
  запрос к таблице в фиче 10.
- **Маршрут «таблица, затем текст»:** фича 10 возвращает идентификаторы
  документов; фича 08 получает их как фильтр; фича 09 строит ответ.
- **Пределы:** не более трёх обращений к языковой модели и заданное время
  на вопрос; при превышении — сообщение и то, что успело получиться.
- **Единая команда:** `ask "<вопрос>" [--route table|text|both]`; команды фич 09
  и 10 остаются для отладки.
- **Замер:** `ask eval --label <метка>` сравнивает маршрут с видом вопроса
  из эталона.
- **Тесты.** Правила по словам-признакам тестируются без модели; для проверки
  маршрутов — подготовленные решения модели.
