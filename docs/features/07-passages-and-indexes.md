## Часть A. Описание для /speckit.specify

### Суть

Система превращает пункты договоров в отрывки для поиска. Один пункт — один
отрывок; слишком длинный пункт делится по подпунктам. К каждому отрывку добавляется
метка: номер договора, стороны, заголовок раздела, номер пункта. Рядом с отрывком
хранятся поля договора, по которым можно фильтровать. Из отрывков строятся два
индекса: для поиска по словам и для поиска по смыслу.

### Зачем

Пункт, вырванный из договора, часто непонятен: «Срок составляет 30 дней» — срок
чего и в каком договоре? Метка возвращает отрывку контекст, и поиск начинает
отличать одинаковые пункты разных договоров. Два индекса нужны потому, что поиск
по словам точно находит номера, названия и термины, а поиск по смыслу находит
то же условие, сформулированное другими словами. Поля-фильтры позволяют искать
только среди договоров нужной стороны или периода.

### Пользователь

Один аналитик. Он запускает построение индексов из командной строки.

### Сценарии

**Сценарий 1. Нарезать договор на отрывки (приоритет P1)**

Проверяется отдельно: нарезать один разобранный договор и просмотреть отрывки.

Критерии приёмки:

1. **Дано** договор разобран на пункты. **Когда** аналитик запускает нарезку.
   **Тогда** каждому пункту соответствует один отрывок со ссылкой на пункт.
2. **Дано** пункт длиннее допустимого размера. **Когда** выполняется нарезка.
   **Тогда** он разделён по подпунктам или абзацам, каждая часть ссылается
   на исходный пункт, и ни одно предложение не разорвано.
3. **Дано** таблица в пункте или приложении. **Когда** выполняется нарезка.
   **Тогда** таблица остаётся в одном отрывке; слишком большая таблица делится
   по строкам с повторением шапки.
4. **Дано** преамбула и блок реквизитов. **Когда** выполняется нарезка. **Тогда**
   они становятся отрывками с указанием вида части.

**Сценарий 2. Метка и поля-фильтры (приоритет P1)**

Проверяется отдельно: посмотреть метку и поля отрывка после нарезки.

Критерии приёмки:

1. **Дано** у договора есть действующие значения номера и сторон. **Когда**
   выполняется нарезка. **Тогда** метка отрывка содержит номер договора, стороны,
   заголовок раздела и номер пункта.
2. **Дано** у договора нет действующих значений полей. **Когда** выполняется
   нарезка. **Тогда** метка содержит идентификатор документа, заголовок раздела
   и номер пункта, а отрывок всё равно создаётся.
3. **Дано** отрывок создан. **Когда** аналитик его просматривает. **Тогда** метка
   и текст пункта хранятся раздельно, и текст пункта не изменён.
4. **Дано** у договора есть действующие значения полей-фильтров из каталога.
   **Когда** выполняется нарезка. **Тогда** эти значения сохранены рядом с каждым
   отрывком договора.

**Сценарий 3. Построить индексы (приоритет P1)**

Проверяется отдельно: построить индексы для нескольких договоров и убедиться, что
число записей в каждом индексе равно числу отрывков.

Критерии приёмки:

1. **Дано** отрывки созданы. **Когда** аналитик запускает построение индексов.
   **Тогда** каждый отрывок присутствует в индексе по словам и в индексе по смыслу.
2. **Дано** индексы построены. **Когда** построение запущено повторно. **Тогда**
   дубликатов не появляется.
3. **Дано** договор разобран заново. **Когда** аналитик перестраивает индексы
   только для него. **Тогда** отрывки остальных договоров не затронуты.
4. **Дано** документ удалён из реестра. **Когда** индексы обновлены. **Тогда** его
   отрывков в индексах нет.

**Сценарий 4. Отчёт о нарезке (приоритет P2)**

Проверяется отдельно: запросить отчёт после нарезки.

Критерии приёмки:

1. **Дано** нарезка выполнена. **Когда** аналитик запрашивает отчёт. **Тогда** он
   видит число отрывков по договорам, распределение их длины, число разделённых
   пунктов и число очень коротких отрывков.
2. **Дано** тот же отчёт. **Когда** аналитик смотрит на полноту. **Тогда** он
   видит, что суммарный текст отрывков покрывает весь текст пунктов.

**Сценарий 5. Несколько вариантов индекса по смыслу (приоритет P3)**

Проверяется отдельно: построить индекс двумя моделями и убедиться, что оба
доступны для поиска.

Критерии приёмки:

1. **Дано** индекс построен одной моделью. **Когда** аналитик строит его второй
   моделью. **Тогда** оба варианта хранятся рядом, и при поиске можно выбрать
   любой.

### Особые случаи

- Пункт состоит только из заголовка: отрывок не создаётся, заголовок попадает
  в метку следующих пунктов.
- Очень короткий пункт («Не применяется.»): отрывок создаётся; он учтён в отчёте.
- Одинаковые типовые пункты в разных договорах: это разные отрывки, различимые
  по метке.
- Модель поиска по смыслу принимает ограниченную длину: отрывок вместе с меткой
  должен помещаться в неё; иначе пункт делится мельче.
- Действующие значения полей договора изменились после решения аналитика: метки
  и поля-фильтры этого договора помечаются как устаревшие до перестроения.
- У договора нет текста или структуры: отрывки не создаются, причина записана.
- Страница имеет флаг «текст получен распознаванием»: отрывки создаются
  и помечаются этим флагом.

### Требования

- **FR-001.** Система должна создавать по одному отрывку на пункт, а длинные
  пункты делить по подпунктам или абзацам без разрыва предложений.
- **FR-002.** Система должна сохранять у каждого отрывка ссылку на пункт
  и на вышестоящий раздел.
- **FR-003.** Система должна формировать метку отрывка и хранить её отдельно
  от неизменённого текста пункта.
- **FR-004.** Система должна сохранять рядом с отрывком действующие значения
  полей-фильтров договора.
- **FR-005.** Система должна строить индекс для поиска по словам с учётом русских
  словоформ и индекс для поиска по смыслу.
- **FR-006.** Система должна перестраивать отрывки и индексы для одного договора,
  не затрагивая остальные, и не создавать дубликатов.
- **FR-007.** Система должна хранить несколько вариантов индекса по смыслу,
  различая их по модели.
- **FR-008.** Система должна выдавать отчёт о нарезке, включая проверку полноты.
- **FR-009.** Нарезка и построение индексов должны выполняться локально.
- **FR-010.** Система должна использовать в метках и фильтрах только действующие
  значения полей (принятые или исправленные аналитиком).

### Сущности

- **Отрывок.** Пункт, раздел, вид части, текст, метка, поля-фильтры, флаги.
- **Запись индекса по словам.** Отрывок и его текст в словарных формах.
- **Запись индекса по смыслу.** Отрывок, модель, вектор.

### Критерии успеха

- **SC-001.** 100% текста пунктов покрыто отрывками.
- **SC-002.** Каждый отрывок прослеживается до пункта, страницы и документа.
- **SC-003.** Построение индексов для 50 договоров занимает не более 30 минут.
  Целевой ориентир; скорость на ноутбуке не измерена.
- **SC-004.** Повторное построение не меняет число отрывков и записей.
- **SC-005.** Ни один отрывок вместе с меткой не превышает допустимую длину
  выбранной модели поиска.

### Вне рамок

- Сам поиск и слияние результатов (фича 08).
- Пояснения к отрывкам, написанные языковой моделью.
- Нарезка с перекрытием и нарезка по смыслу: пробуются, только если замеры
  покажут, что нарезки по пунктам недостаточно.

### Допущения

- Один пункт — один смысловой блок.
- Набор — несколько тысяч отрывков.

### Минимальная версия для сквозного прототипа

Отрывок на пункт без деления длинных пунктов; метка из идентификатора документа,
заголовка раздела и номера пункта; оба индекса в простейшем виде; без
полей-фильтров и отчёта.

## Часть B. Технические заметки для /speckit.plan

- **Что уходит в индекс по смыслу:** метка и текст вместе. Что уходит в проверку
  цитат и показывается человеку: только текст пункта.
- **Что уходит в индекс по словам:** метка и текст, приведённые к словарным формам;
  номера договоров и пунктов сохраняются как есть, без приведения.
- **Поиск по словам.** Выбрать между встроенным полнотекстовым поиском хранилища
  по заранее приведённому тексту и BM25 в памяти процесса; записать выбор
  в `docs/tech-context.md`. Замер — в фиче 08.
- **Модель поиска по смыслу.** BGE-M3 по умолчанию. Для FRIDA учесть приставку
  `search_document:` и предел в 512 фрагментов слов.
- **Допустимый размер отрывка:** задаётся в настройках в расчёте на самую
  ограниченную из используемых моделей.
- **Память.** При построении индекса нужна только модель поиска по смыслу;
  языковую модель держать выгруженной.
- **Таблица хранилища:** `passage` и таблица векторов с указанием модели.
- **Команды** (ориентир): `index build [идентификатор…] [--model M]`,
  `index report`, `passage <идентификатор пункта>`.
- **Тесты.** Нарезка и метки тестируются без моделей на синтетической структуре.
