## Часть A. Описание для /speckit.specify

### Суть

Одна страница в браузере, которая работает только на ноутбуке аналитика. На ней
четыре области: окно вопросов и ответов, таблица полей договора, просмотр страницы
договора с подсветкой и список документов. Щелчок по цитате в ответе или
по значению в таблице открывает страницу договора, на которой нужное место
выделено. В таблице полей аналитик подтверждает или исправляет значения, ждущие
просмотра. Обработка договоров по-прежнему запускается из командной строки.

### Зачем

Главная работа аналитика — проверка по источнику: верно ли значение, есть ли
в договоре приведённая цитата. В командной строке для этого нужно открыть PDF,
найти страницу и глазами отыскать фразу; для полутора тысяч значений это часы.
Экран сокращает проверку до одного щелчка. Он же позволяет показать работу системы
людям, которые не пользуются командной строкой.

### Пользователь

Один аналитик на своём ноутбуке. При показе — те, кому он показывает экран
на том же ноутбуке.

### Сценарии

**Сценарий 1. Вопрос и переход к источнику (приоритет P1)**

Проверяется отдельно: задать вопрос и перейти по цитате.

Критерии приёмки:

1. **Дано** экран открыт. **Когда** аналитик вводит вопрос. **Тогда** он видит
   ответ, у каждого утверждения — цитату и ссылку на договор, пункт и страницу.
2. **Дано** ответ с цитатами. **Когда** аналитик щёлкает по цитате. **Тогда**
   рядом открывается нужная страница договора, и цитата на ней выделена.
3. **Дано** система ответила «не найдено». **Когда** аналитик смотрит ответ.
   **Тогда** он видит, какие пункты были просмотрены, и может открыть любой из них.
4. **Дано** часть ответа не прошла проверку цитат. **Когда** ответ показан.
   **Тогда** эта часть визуально отличается от подтверждённой.
5. **Дано** ответ ещё формируется. **Когда** аналитик ждёт. **Тогда** видно, что
   система работает, а новый вопрос задать нельзя до завершения.

**Сценарий 2. Таблица полей договора (приоритет P1)**

Проверяется отдельно: открыть договор и перейти от значения к источнику.

Критерии приёмки:

1. **Дано** аналитик выбрал договор. **Когда** открывается таблица полей. **Тогда**
   для каждого поля видны значение, статус и цитата, поля сгруппированы как
   в каталоге.
2. **Дано** значение с цитатой. **Когда** аналитик щёлкает по нему. **Тогда**
   открывается страница договора с выделенной цитатой.
3. **Дано** значения с разными статусами. **Когда** аналитик смотрит таблицу.
   **Тогда** значения, требующие просмотра, и отклонённые заметны сразу, а причина
   видна без дополнительных действий.

**Сценарий 3. Просмотр и исправление значений (приоритет P2)**

Проверяется отдельно: подтвердить одно значение, исправить другое.

Критерии приёмки:

1. **Дано** значение ждёт просмотра. **Когда** аналитик подтверждает его. **Тогда**
   статус меняется на «принято» с отметкой о подтверждении человеком.
2. **Дано** значение ждёт просмотра. **Когда** аналитик вводит исправление.
   **Тогда** исправленное значение сохраняется, а значение системы остаётся видно.
3. **Дано** значение ждёт просмотра. **Когда** аналитик отмечает, что в договоре
   его нет. **Тогда** статус меняется на «не найдено» с отметкой о подтверждении.
4. **Дано** есть очередь просмотра по всему набору. **Когда** аналитик открывает
   её. **Тогда** он переходит от значения к значению, не возвращаясь к списку.

**Сценарий 4. Список документов (приоритет P2)**

Проверяется отдельно: открыть список после обработки нескольких договоров.

Критерии приёмки:

1. **Дано** в реестре есть документы. **Когда** аналитик открывает список. **Тогда**
   он видит идентификатор, имя, номер договора, стороны и состояние каждого этапа.
2. **Дано** у документа есть состояние «требует просмотра». **Когда** аналитик
   смотрит на него. **Тогда** видна причина.
3. **Дано** список. **Когда** аналитик выбирает документ. **Тогда** открываются
   его таблица полей и просмотр страниц.

**Сценарий 5. Маршрут и условия в ответе (приоритет P3)**

Проверяется отдельно: задать вопрос на подсчёт и вопрос по тексту.

Критерии приёмки:

1. **Дано** ответ получен. **Когда** аналитик его читает. **Тогда** он видит
   выбранный маршрут и применённые условия отбора.
2. **Дано** ответ получен. **Когда** аналитик выбирает другой маршрут. **Тогда**
   вопрос выполняется заново по выбранному маршруту.
3. **Дано** ответ по таблице со списком договоров. **Когда** аналитик щёлкает
   по договору в списке. **Тогда** открывается этот договор.

### Особые случаи

- Цитата расположена на двух страницах: открывается первая, выделены обе части,
  переход на вторую — одним действием.
- Место цитаты на странице неизвестно: страница открывается без выделения,
  и об этом сказано.
- Страница договора — скан без текста: страница показывается, выделения нет.
- Документ удалён из реестра, а ответ на него ссылается: ссылка показана как
  недоступная.
- Результаты этапа устарели после повторной обработки: это видно рядом
  со значением или ответом.
- Языковая модель не запущена: вопросы недоступны с понятным сообщением, таблица
  полей и просмотр работают.
- Экран открыт в двух вкладках: изменения в одной видны в другой после обновления.
- Попытка открыть экран с другого устройства в сети: соединение не принимается.
- Очень длинный договор: переход между страницами не требует загрузки всего
  документа.
- Сеть отключена: экран работает полностью.

### Требования

- **FR-001.** Экран должен принимать соединения только с той же машины.
- **FR-002.** Экран должен работать без подключения к сети и не загружать никаких
  частей из интернета.
- **FR-003.** Экран должен содержать окно вопросов и ответов, использующее тот же
  порядок ответа, что и командная строка.
- **FR-004.** Экран должен показывать для каждого утверждения ответа цитату,
  ссылку и исход проверки.
- **FR-005.** Экран должен открывать страницу договора с выделенной цитатой
  по щелчку на цитате или значении.
- **FR-006.** Экран должен показывать таблицу полей договора со значениями,
  статусами, причинами и цитатами.
- **FR-007.** Экран должен позволять подтвердить значение, исправить его или
  отметить отсутствие, сохраняя значение системы.
- **FR-008.** Экран должен показывать очередь просмотра по всему набору.
- **FR-009.** Экран должен показывать список документов с состояниями этапов.
- **FR-010.** Экран должен показывать маршрут ответа и применённые условия
  и позволять выбрать маршрут.
- **FR-011.** Экран не должен запускать этапы обработки договоров.
- **FR-012.** Экран должен обрабатывать вопросы по одному и показывать, что ответ
  формируется.
- **FR-013.** Каждый вопрос обрабатывается независимо; прежние вопросы и ответы
  текущего сеанса видны на экране, но не влияют на новый ответ.
- **FR-014.** Экран не должен иметь учётных записей и разграничения прав.

### Сущности

Новых сущностей нет. Экран показывает документы, страницы, пункты, значения полей,
ответы и решения аналитика, созданные другими фичами, и записывает решения
аналитика так же, как фича 06.

### Критерии успеха

- **SC-001.** От цитаты в ответе до выделенного места в договоре — один щелчок.
- **SC-002.** Проверка одного значения из очереди просмотра требует не более трёх
  действий.
- **SC-003.** Экран полностью работает при отключённой сети.
- **SC-004.** С другого устройства в той же сети экран недоступен.
- **SC-005.** Страница договора с выделением открывается не более чем
  за 2 секунды. Целевой ориентир.
- **SC-006.** Решение, принятое на экране, видно в выгрузке таблицы полей
  и в ответах по таблице.

### Вне рамок

- Запуск чтения, извлечения и индексации с экрана.
- Загрузка документов через экран.
- Учётные записи, доступ по сети, работа нескольких людей.
- Диалог с памятью о предыдущих вопросах.
- Таблица результатов замеров и графики.
- Редактирование каталога полей.
- Мобильная версия.

### Допущения

- Экраном пользуется один человек на том же ноутбуке, где работает система.
- Чтение сохранило положение строк на странице (фича 03).

### Минимальная версия

Сценарий 1: окно вопросов, ответ с цитатами, переход к странице с выделением.
Её можно собрать сразу после сквозного прототипа, если нужен ранний показ.

## Часть B. Технические заметки для /speckit.plan

- **Выбор библиотеки.** Кандидаты: Gradio, Chainlit, Streamlit. Проверить
  на маленьком образце до плана: готовое окно чата; таблица с щелчком по строке;
  показ изображения страницы рядом с чатом; работа без сети (шрифты и скрипты
  не грузятся из интернета); отключение телеметрии; привязка к локальному адресу.
  Выбор записать в `docs/tech-context.md`.
- **Показ страницы.** Страница PDF превращается в изображение по требованию, поверх
  рисуются прямоугольники строк цитаты из данных фичи 03. Изображения можно
  хранить во временной папке внутри папки данных.
- **Место цитаты.** Цитата → диапазон символов очищенного текста → строки
  и страницы через таблицу соответствия из фичи 03.
- **Адрес:** только `127.0.0.1`.
- **Общий код.** Экран вызывает те же функции, что команда `ask` и команды
  просмотра из фичи 06; своей логики ответов и статусов у него нет.
- **Одна модель — один запрос.** Вопросы ставятся в очередь; пока модель занята,
  ввод недоступен.
- **Команда** (ориентир): `ui` — запускает экран и печатает адрес.
- **Тесты.** Вычисление места цитаты и сборка данных для экрана тестируются без
  браузера; для экрана — короткая ручная проверка по сценариям.
