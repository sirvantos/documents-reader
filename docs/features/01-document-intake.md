# Фича 01. Приём документов и реестр

> **Как использовать.** Часть A вставьте как аргумент `/speckit.specify`
> (в старых версиях Spec Kit — `/specify`). Часть B вставьте как аргумент
> `/speckit.plan`; общие решения агент возьмёт из `docs/tech-context.md`, на который
> ссылается конституция. Перед `/speckit.plan` полезно запустить `/speckit.clarify`.

## Часть A. Описание для /speckit.specify

### Суть

Пользователь указывает папку или файл с договорами. Система регистрирует каждый
договор в реестре: присваивает постоянный идентификатор, сохраняет собственную
неизменённую копию файла и определяет, какие страницы содержат готовый
текст, а какие являются сканами. Пользователь может посмотреть список договоров
и состояние каждого по этапам обработки.

### Зачем

Все последующие этапы (чтение, извлечение, поиск, ответы) ссылаются на документ
по идентификатору и должны уметь вернуться к исходному файлу. Реестр — единственное
место, где известно, какие документы есть в системе и что с каждым уже сделано.
Разделение страниц на «готовый текст» и «скан» показывает, какие страницы можно
читать, а какие на первом этапе останутся непрочитанными.

### Пользователь

Один аналитик, который ведёт проверку концепции на своём ноутбуке. Приём документов
выполняется из командной строки.

### Сценарии

**Сценарий 1. Добавить папку договоров (приоритет P1)**

Аналитик указывает папку с файлами договоров и получает отчёт: какие файлы добавлены
и с какими идентификаторами, какие пропущены и почему.

Проверяется отдельно: достаточно папки с несколькими файлами и просмотра отчёта.

Критерии приёмки:

1. **Дано** папка с пятью PDF-файлами, которых нет в реестре. **Когда** аналитик
   добавляет папку. **Тогда** в реестре появляется пять документов, у каждого есть
   идентификатор, исходное имя файла и число страниц.
2. **Дано** в папке есть файл неподдерживаемого формата. **Когда** аналитик добавляет
   папку. **Тогда** остальные файлы добавлены, а этот указан в отчёте с причиной
   «формат не поддерживается».
3. **Дано** документ добавлен. **Когда** исходный файл в папке пользователя
   перемещён или удалён. **Тогда** система по-прежнему имеет доступ к своей копии,
   побайтно совпадающей с исходным файлом на момент добавления.

**Сценарий 2. Повторное добавление не создаёт дубликатов (приоритет P1)**

Аналитик повторно добавляет ту же папку, например после того, как положил в неё
новые файлы. Уже известные документы не дублируются.

Проверяется отдельно: добавить папку дважды и сравнить число документов.

Критерии приёмки:

1. **Дано** папка уже добавлена. **Когда** аналитик добавляет её снова без изменений.
   **Тогда** число документов в реестре не меняется, а отчёт показывает для каждого
   файла «уже есть» и его идентификатор.
2. **Дано** файл с тем же содержимым, но другим именем. **Когда** аналитик его
   добавляет. **Тогда** новый документ не создаётся; отчёт указывает на существующий.
3. **Дано** файл с тем же именем, но другим содержимым. **Когда** аналитик его
   добавляет. **Тогда** создаётся новый документ, а отчёт предупреждает о совпадении
   имён.

**Сценарий 3. Определение вида страниц (приоритет P1)**

При добавлении система определяет для каждой страницы, как её нужно будет читать:
страница с готовым текстом, скан без текста или скан со встроенным текстом
сомнительного качества.

Проверяется отдельно: добавить один цифровой PDF, один скан и один смешанный файл
и посмотреть результат по страницам.

Критерии приёмки:

1. **Дано** PDF, выгруженный из текстового редактора. **Когда** он добавлен.
   **Тогда** все его страницы помечены как «готовый текст».
2. **Дано** PDF, полученный со сканера. **Когда** он добавлен. **Тогда** все его
   страницы помечены как «скан».
3. **Дано** PDF, в котором основная часть выгружена из редактора, а страница
   с подписями отсканирована. **Когда** он добавлен. **Тогда** страницы помечены
   по отдельности, и страница с подписями помечена как «скан».
4. **Дано** скан, в который сканер встроил распознанный текст. **Когда** он добавлен.
   **Тогда** его страницы помечены как «скан со встроенным текстом», а не как
   «готовый текст».

**Сценарий 4. Посмотреть реестр (приоритет P2)**

Аналитик смотрит список документов: идентификатор, имя, число страниц,
сколько страниц каждого вида, состояние по каждому этапу обработки.

Проверяется отдельно: после добавления документов вывести список.

Критерии приёмки:

1. **Дано** в реестре есть документы. **Когда** аналитик запрашивает список.
   **Тогда** для каждого документа видны идентификатор, исходное имя, число страниц
   и состояние каждого этапа.
2. **Дано** документ только что добавлен. **Когда** аналитик смотрит список.
   **Тогда** все этапы обработки для него показаны как «ожидает».
3. **Дано** аналитик указывает идентификатор. **Когда** он запрашивает сведения
   об одном документе. **Тогда** он видит те же данные и вид каждой страницы.

**Сценарий 5. Удалить документ (приоритет P3)**

Аналитик удаляет документ, добавленный по ошибке, вместе со всем, что система
по нему накопила.

Проверяется отдельно: добавить документ, удалить и убедиться, что его нет в списке.

Критерии приёмки:

1. **Дано** документ есть в реестре. **Когда** аналитик удаляет его и подтверждает
   действие. **Тогда** документ, его копия и все связанные с ним результаты
   исчезают из системы.
2. **Дано** документ удалён. **Когда** аналитик добавляет тот же файл снова.
   **Тогда** он добавляется как новый документ.
3. **Дано** аналитик запросил удаление. **Когда** он не подтвердил действие.
   **Тогда** ничего не удаляется.

### Особые случаи

- Файл защищён паролем или повреждён: не добавляется, причина указана в отчёте.
- Файл без страниц или нулевого размера: не добавляется, причина указана.
- Файл Word или изображение (JPEG, PNG): не добавляется, в отчёте указана причина
  и предложено сохранить документ в PDF.
- В документе есть страницы вида «скан»: документ добавляется, отчёт предупреждает,
  что такие страницы не читаются без распознавания (фича 13), и называет их номера.
- В документе есть страницы вида «скан со встроенным текстом»: документ добавляется,
  отчёт предупреждает, что текст получен распознаванием и может содержать ошибки.
- Очень большой файл (сотни страниц): добавляется, отчёт предупреждает о размере.
- Папка содержит вложенные папки: файлы из них тоже добавляются.
- Страница содержит казахские буквы: на этом этапе не проверяется; проверка
  относится к чтению (фича 03).
- Файл является дополнительным соглашением к другому договору: система этого
  не распознаёт и регистрирует его как самостоятельный документ.
- Добавление прервано на середине папки: уже добавленные документы остаются,
  повторный запуск добавляет оставшиеся.

### Требования

- **FR-001.** Система должна принимать на вход путь к файлу или к папке, включая
  вложенные папки.
- **FR-002.** Система должна поддерживать PDF; файлы других форматов не добавляются
  и попадают в отчёт с причиной.
- **FR-003.** Система должна присваивать каждому документу постоянный идентификатор,
  достаточно короткий, чтобы вводить его вручную.
- **FR-004.** Система должна хранить собственную копию исходного файла, побайтно
  совпадающую с исходным, и никогда её не изменять.
- **FR-005.** Система должна распознавать повторное добавление по содержимому файла,
  независимо от имени, и не создавать второй документ.
- **FR-006.** Система должна сохранять для документа исходное имя файла, число
  страниц, дату добавления и необязательную заметку пользователя.
- **FR-007.** Система должна определять для каждой страницы PDF её вид: «готовый
  текст», «скан» или «скан со встроенным текстом», и показывать в отчёте число
  страниц каждого вида по каждому документу.
- **FR-008.** Система должна вести для каждого документа состояние по каждому этапу
  обработки: «ожидает», «готово», «требует просмотра», «ошибка»; для двух последних
  обязательна причина.
- **FR-009.** Система должна выдавать после каждого добавления отчёт, в котором
  каждый входной файл отнесён ровно к одной группе: добавлен, уже есть, не добавлен
  (с причиной).
- **FR-010.** Система должна показывать список документов и сведения об одном
  документе по идентификатору.
- **FR-011.** Система должна удалять документ со всеми связанными результатами
  только после явного подтверждения.
- **FR-012.** Система должна фиксировать каждый запуск обработки: когда, какой этап,
  какой версией кода и с какими настройками. Этой записью пользуются все
  последующие фичи.
- **FR-013.** Система должна работать без подключения к сети и не передавать
  содержимое файлов за пределы машины.

### Сущности

- **Документ.** Один договор. Идентификатор, исходное имя файла, отпечаток
  содержимого, число страниц, дата добавления, заметка. Предусмотрена
  ссылка на родительский документ; на первом этапе она всегда пуста.
- **Страница.** Принадлежит документу. Номер, вид страницы.
- **Состояние этапа.** Для пары «документ, этап»: состояние и причина.
- **Запуск.** Одно выполнение этапа обработки: время, этап, версия, настройки, метка.

### Критерии успеха

- **SC-001.** Все 50 договоров эталонного набора добавляются одной командой; каждый
  файл либо добавлен, либо указан в отчёте с причиной; ни один файл не пропущен
  без записи.
- **SC-002.** Повторное добавление той же папки создаёт ноль новых документов.
- **SC-003.** Для 100% добавленных документов копия в системе побайтно совпадает
  с исходным файлом.
- **SC-004.** На выборке из 10 договоров, проверенных вручную, вид страницы
  определён верно не менее чем для 95% страниц.
- **SC-005.** Добавление 50 договоров занимает не более 5 минут на ноутбуке
  пользователя.
- **SC-006.** Аналитик может по идентификатору из любого последующего результата
  открыть исходный файл.

### Вне рамок

- Чтение текста и разбор структуры (фичи 03–04).
- Распознавание сканов (фича 13, конституция 3.0.0).
- Связи между документами, в том числе «договор — дополнительное соглашение».
- Определение типа договора и языка документа.
- Права доступа, несколько пользователей.
- Графический интерфейс (список документов на веб-экране — фича 12).
- Автоматическое отслеживание папки и загрузка из почты или других систем.

### Допущения

- Договоры поступают как файлы PDF — с текстом или сканы (конституция 3.0.0),
  один файл — один договор.
- Приложения к договору находятся в том же файле, что и сам договор.
- Объём набора — десятки документов; скорость приёма не критична.

### Минимальная версия для сквозного прототипа

Сценарии 1 и 2 для PDF, вид страницы в упрощённом виде («есть текст» или «нет
текста»), список документов с идентификатором и числом страниц. Удаление и заметки —
позже.

## Часть B. Технические заметки для /speckit.plan

- **Отпечаток содержимого:** SHA-256 от байтов файла. По нему определяется дубликат
  и проверяется неизменность копии.
- **Идентификатор:** короткий последовательный, например `D-0001`. Он используется
  в командной строке, в эталонных файлах и в ссылках на источник.
- **Хранение копий:** папка данных вне репозитория, путь задаётся в настройках.
  Имя файла копии строится из идентификатора или отпечатка, не из исходного имени.
- **Вид страницы.** «Готовый текст»: на странице есть извлекаемый текст и нет
  изображения, занимающего почти всю страницу. «Скан»: извлекаемого текста нет или
  почти нет, есть изображение на всю страницу. «Скан со встроенным текстом»: есть
  и изображение на всю страницу, и текст. Пороговые значения подобрать на 10
  договорах из критерия SC-004.
- **Изображения страниц** при приёме не создаются. Их по требованию создаёт
  веб-экран (фича 12), когда показывает страницу с подсветкой цитаты.
- **Таблицы хранилища,** которые создаёт эта фича: `document`, `page`,
  `stage_status`, `run`. Поле `parent_document_id` создаётся и остаётся пустым.
- **Команды** (ориентир): `add <путь>`, `list`, `show <идентификатор>`,
  `remove <идентификатор>`.
- **Проверки без модели.** В этой фиче нет обращений к языковой модели.
- **Тесты.** Нужны синтетические файлы: цифровой PDF, PDF из одних изображений,
  смешанный PDF, PDF с изображением и скрытым текстовым слоем, повреждённый файл,
  файл с паролем. Реальные договоры в тесты репозитория не попадают (принцип I).
