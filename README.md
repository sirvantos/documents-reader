# documents-reader

Локальная проверка концепции (PoC): чтение русскоязычных договоров, извлечение
ключевых фактов в таблицу, поиск по тексту и ответы на вопросы со ссылкой на пункт
договора. Всё работает на одном ноутбуке, без отправки данных за пределы машины.

Цель PoC — получить измеренные цифры качества по каждому этапу (чтение, извлечение,
поиск, ответ) и по ним решить, стоит ли строить систему для полного архива.

## Состояние

| Фича | Что делает | Состояние |
|---|---|---|
| 01 | Приём документов и реестр | готово ([спецификация](specs/001-document-intake/spec.md)) |
| 02–12 | Эталонный набор, чтение текста, структура, извлечение полей, поиск, ответы, веб-экран | впереди ([описания](docs/features/)) |

Карта фич и зависимости между ними — в [docs/tech-context.md](docs/tech-context.md#карта-фич).

## Главные правила

- **Данные не покидают машину.** Договоры, извлечённые значения, вопросы и ответы
  обрабатываются только локально; модели скачиваются заранее, сеть во время работы
  не нужна.
- **Реальные договоры не попадают в репозиторий.** Они лежат в папке данных вне
  репозитория (`DOCREADER_DATA_DIR`); программа отказывается работать с папкой данных
  внутри репозитория и с нелокальной базой данных. В репозитории — только код и
  синтетические примеры, которые тесты создают сами.
- **Исходный файл — источник истины.** Система хранит неизменную побайтную копию
  каждого файла, и любой результат можно проследить до документа и страницы.

Полный список принципов — в [конституции проекта](.specify/memory/constitution.md);
она имеет приоритет над остальными документами.

## Требования

- Python 3.11+ и [uv](https://docs.astral.sh/uv/)
- PostgreSQL 17, запущенный локально (Unix-сокет или `localhost`)
- macOS (Apple Silicon) или Linux x86_64
- Для тестов достаточно Docker — см. «Тесты»

## Установка

```
uv sync
cp .env.example .env              # поправить значения под эту машину
createdb docreader
uv run --env-file .env docreader migrate
```

Переменные окружения описаны в [.env.example](.env.example). Значения для каждой
машины лежат в её собственном `.env` (и `.env.bench` для замера движка); эти файлы
не коммитятся. Они подключаются к каждой команде флагом `--env-file`, а не глобально,
поэтому автотесты их не видят. Сокращения для `~/.zprofile`:

```
alias dr='uv run --env-file .env docreader'
alias drb='uv run --env-file .env.bench docreader'
```

Пороги определения вида страниц и предупреждений можно задать в
`$DOCREADER_DATA_DIR/settings.toml` (формат — в [contracts/cli.md](specs/001-document-intake/contracts/cli.md#окружение)).

## Использование

| Команда | Что делает |
|---|---|
| `docreader add <путь>... [--note ТЕКСТ] [--label МЕТКА] [--json]` | добавляет файлы и папки (рекурсивно); печатает отчёт: добавлено / уже есть / не добавлено с причиной |
| `docreader list [--json]` | список документов: страницы по видам и состояние этапов обработки |
| `docreader show <ID> [--json]` | сведения о документе: отпечаток, путь к копии, вид каждой страницы |
| `docreader verify [<ID>...]` | сверяет копии с отпечатками SHA-256 |
| `docreader remove <ID> [--yes]` | удаляет документ со всеми результатами (после подтверждения) |
| `docreader reclassify [<ID>...]` | пересчитывает вид страниц по текущим порогам |
| `docreader page-kinds-check <labels.csv>` | сверяет виды страниц с ручной разметкой |
| `docreader migrate` | применяет миграции базы данных |

Команды запускаются как `uv run docreader …`. Подробно (вывод, JSON, коды завершения) —
в [contracts/cli.md](specs/001-document-intake/contracts/cli.md), пошаговая проверка —
в [quickstart.md](specs/001-document-intake/quickstart.md).

## Тесты

Одной командой в Docker — без установки Python и PostgreSQL:

```
docker compose run --rm tests          # аргументы pytest — в конце, например -k note -x
docker compose down                    # остановить временную базу
```

Тесты работают с временной базой в памяти, без доступа в интернет; репозиторий
подключается только для чтения. После изменения зависимостей — `docker compose build tests`.

Без Docker, с локальным PostgreSQL (роль с правом `CREATEDB`):

```
DOCREADER_TEST_DATABASE_URL=postgresql:///postgres uv run pytest
uv run pytest tests/unit               # только модульные тесты, база не нужна
```

Каждый прогон создаёт и удаляет временную базу `docreader_test_*`. Тесты с реальной
моделью (`pytest -m real_model`) по умолчанию исключены и запускаются только на ноутбуке.

