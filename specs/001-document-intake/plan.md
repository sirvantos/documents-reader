## Summary

Команда `docreader` с подкомандами регистрирует PDF-договоры в реестре на PostgreSQL:
выдаёт идентификатор `D-0001` из счётчика, который только растёт; кладёт неизменяемую
копию в папку данных под именем `<sha256>.pdf`; распознаёт дубликаты по SHA-256;
по каждой странице считает число символов текстового слоя и долю площади под
изображениями и по ним относит страницу к «готовому тексту», «скану» или «скану со
встроенным текстом». Каждый файл обрабатывается атомарно, каждый входной файл попадает
ровно в одну группу отчёта. Ведутся записи о запусках (`run`), состояния пяти этапов
документа (`stage_status`) и журнал удалений. Языковая модель не используется.
PDF открывается через `pypdfium2`; этот выбор сделан раньше, чем предусматривает
tech-context (см. «Отступления»).

## Technical Context

**Language/Version**: Python 3.12 (tech-context: 3.11 или новее), окружение — `uv`

**Primary Dependencies**: `pypdfium2` (открытие PDF, показатели страниц — research R-1),
`psycopg[binary]` 3 (PostgreSQL, R-6); CLI — стандартный `argparse` (R-7), настройки —
стандартный `tomllib` (R-8). Dev: `pytest`, `reportlab`, `Pillow` (синтетические PDF, R-10).
Точные версии фиксируются в `uv.lock`.

**Storage**: PostgreSQL 17 (Homebrew), только локальное подключение; таблицы `run`,
`document`, `page`, `stage_status`, `document_counter`, `deletion_log`,
`schema_migrations` ([data-model.md](data-model.md)). Копии файлов и отчёты лежат
в `$DOCREADER_DATA_DIR` вне репозитория. Расширение pgvector в этой фиче не нужно.

**Testing**: `pytest`; модульные тесты (распознавание формата, правило вида страницы,
объединение прямоугольников, идентификаторы, настройки) и интеграционные (CLI на временной
базе PostgreSQL и временной папке данных, синтетические PDF генерируются в фикстурах).

**Target Platform**: macOS, Apple M3 Pro, 36 ГБ; без сети.

**Project Type**: CLI-приложение, один пакет.

**Performance Goals**: 50 договоров по десяткам страниц — не более 5 минут (SC-005);
ожидается порядок секунд: хэширование и подсчёт объектов страниц без отрисовки.

**Constraints**: без сети (FR-013); копия не изменяется (FR-004); нет частично
добавленных документов; данные и вывод по реальным договорам не попадают к ИИ-агенту.

**Scale/Scope**: десятки документов (50 в эталонном наборе), один пользователь;
8 подкоманд; 7 таблиц.

Неясностей (NEEDS CLARIFICATION) не осталось: все открытые вопросы закрыты в
[research.md](research.md).

## Ключевые решения по реализации

Подробности и альтернативы — в [research.md](research.md); схема — в
[data-model.md](data-model.md); интерфейс — в [contracts/cli.md](contracts/cli.md).

1. **Порядок обработки файла** (`add`): скрытый/пустой → сигнатура → SHA-256 → поиск
   по отпечатку (в базе и среди уже обработанных в этом запуске) → открытие PDF и
   показатели всех страниц → копия во временный файл, `fsync`, сверка хэша,
   переименование в `originals/<sha256>.pdf` (существующая копия с совпавшим хэшем
   используется повторно) → одна транзакция: счётчик `FOR UPDATE`, `document`, `page`,
   пять строк `stage_status` в `pending` → предупреждения. PDF открывается до копирования,
   поэтому повреждённые файлы в папку данных не попадают.
2. **Вид страницы**: правило R-2, пороги из настроек, применённые значения — в
   `run.settings`. Минимальная версия для сквозного прототипа: без `scan_with_text`
   (порог покрытия не используется), только «есть текст / нет текста»; полная версия
   добавляет порог покрытия — схема одна и та же.
3. **Идентификатор**: счётчик в той же транзакции; ввод без учёта регистра и нулей.
4. **Удаление**: подтверждение вводом идентификатора или `--yes`; в одной транзакции
   запись в `deletion_log` и каскадное удаление; файл копии удаляется после фиксации.
5. **Прерывание**: Ctrl-C завершает текущий файл без фиксации, печатает частичный отчёт,
   код 130; запуск остаётся с пустым `finished_at`.
6. **Проверки без модели**: ни одного обращения к языковой модели.
