## R-1. Библиотека для открытия PDF

**Decision**: `pypdfium2` (обёртка над PDFium, лицензии Apache-2.0 / BSD-3-Clause).

**Rationale**:
- Фиче 01 нужны: число страниц, признак «защищён паролем / повреждён», число символов
  текстового слоя на странице, положение изображений на странице, режим отрисовки текста
  (невидимый текст — признак слоя распознавания). Всё это PDFium даёт напрямую.
- Лицензия разрешительная — учтено предупреждение tech-context о лицензиях, требующих
  открывать исходный код (PyMuPDF — AGPL).
- Быстрая (C-библиотека): 50 договоров по десяткам страниц укладываются в SC-005 с большим
  запасом.
- Сразу закрывает задачи последующих фич: текст с координатами символов (фича 03) и
  отрисовка страницы в картинку для подсветки цитаты (фича 12) — без второй зависимости
  (принцип VIII).
- Работает без сети, телеметрии нет.

**Alternatives considered**:
- *PyMuPDF* — богатый API, но AGPL; отклонена по лицензии.
- *pdfplumber / pdfminer.six* — MIT, хорошие координаты, но медленнее, не даёт отрисовку
  без pypdfium2 (pdfplumber и так зависит от него), режим отрисовки текста доступен хуже.
- *pypdf* — чистый Python, хорошо определяет шифрование, но координаты и изображения
  на странице придётся вычислять вручную через разбор потока содержимого.

**Отступление от tech-context**: в tech-context выбор библиотеки чтения PDF отнесён к плану
фичи 03. Фича 01 вынуждена открывать PDF раньше, поэтому выбор сделан здесь — см. раздел
«Отступления» в [plan.md](plan.md).

## R-2. Правило определения вида страницы

**Decision**: для каждой страницы считаются три показателя и по ним — вид:

| Показатель | Как считается |
|---|---|
| `char_count` | число непробельных символов текстового слоя страницы |
| `image_coverage` | доля площади страницы (по CropBox), покрытая объединением прямоугольников всех изображений, включая вложенные в формы (границы вложенных изображений переводятся в координаты страницы через матрицы форм); 0..1 |
| `invisible_text_share` | доля текстовых объектов с режимом отрисовки «невидимый» (режим 3) — только для диагностики |

Правило (пороги — в настройках):

```
has_text   = char_count >= page_kinds.text_min_chars          (по умолчанию 20)
full_image = image_coverage >= page_kinds.full_image_coverage  (по умолчанию 0.85)

не has_text                → scan            («скан»)
has_text и full_image      → scan_with_text  («скан со встроенным текстом»)
has_text и не full_image   → text            («готовый текст»)
```

**Rationale**:
- Повторяет определения из части B; страница без текста при любом количестве изображений
  становится «сканом», потому что на первом этапе её всё равно нечем прочитать
  (принцип VII: аналитик получает предупреждение, а не молчаливый пропуск). Это же
  правило в минимальной версии сводится к «есть текст / нет текста».
- Объединение прямоугольников, а не максимум одного изображения: часть сканеров режет
  страницу на полосы.
- `invisible_text_share` сохраняется, но в правило не входит (принцип V: сначала простое
  правило, усложнение — только если замер SC-004 покажет ошибки, например у цифровых
  страниц с фоновой картинкой на весь лист).
- Показатели хранятся в базе, поэтому подбор порогов на 10 договорах (SC-004) не требует
  повторного открытия файлов: команда `reclassify` пересчитывает вид по сохранённым
  показателям.

**Alternatives considered**:
- Отрисовка страницы и анализ пикселей — медленнее, лишняя работа; изображения страниц при
  приёме не создаются (часть B).
- Четвёртый вид «пустая страница» — в спецификации три вида; пустая страница честно
  попадает в «скан» с предупреждением и номером.

**Подбор порогов**: делает аналитик на реальных договорах сам, без агента (раздел
«Разработка с ИИ-агентом» конституции): размечает виды страниц 10 договоров в CSV в папке
данных, запускает `page-kinds-check`, при необходимости меняет пороги в `settings.toml`,
`reclassify`, снова `page-kinds-check`. Итоговые пороги записываются в tech-context; цифра
точности — в таблицу результатов (фича 02), а не в репозиторий.

## R-3. Идентификатор документа

**Decision**: строка `D-` + номер, дополненный нулями до 4 знаков (`D-0001`, … `D-9999`,
далее `D-10000`). Номер выдаётся из таблицы-счётчика с одной строкой, которая
блокируется и увеличивается в той же транзакции, что вставляет документ.

**Rationale**: нет пропусков номеров при откате транзакции (у `SEQUENCE` они были бы);
счётчик никогда не уменьшается — удалённый номер повторно не выдаётся (FR-003).
Ввод принимается без учёта регистра и без ведущих нулей (`d-1` ≡ `D-0001`).

**Alternatives considered**: `SEQUENCE` (пропуски при сбоях); `max(seq)+1`
(повторно выдаст номер после удаления последнего документа); UUID/хэш (не вводится вручную).

## R-4. Хранение копий

**Decision**: `<DATA_DIR>/originals/<sha256>.pdf`, права только на чтение (0444).
Порядок: файл открывается и проверяется → копируется во временный файл в той же папке →
`fsync` → SHA-256 копии сверяется с отпечатком исходного → атомарное переименование →
запись в базу одной транзакцией.

**Rationale**:
- Имя по отпечатку известно до выдачи идентификатора, поэтому копия пишется до транзакции,
  а сбой между копированием и транзакцией оставляет только файл, который повторный запуск
  узнаёт по имени и сверяет по хэшу. Частично добавленных документов не бывает
  (крайний случай «добавление прервано»).
- Исходное имя в путь не попадает (часть B).
- Если исходный файл изменился между хэшированием и копированием, сверка это ловит —
  файл получает «не добавлен: файл изменился во время добавления».

**Alternatives considered**: имя по идентификатору (`D-0001.pdf`) — удобнее глазами, но
идентификатор появляется только внутри транзакции; при сбое остаются копии без документа
и неочевидно, чьи они. Путь к копии всё равно выводит `show`, поэтому удобство не теряется.

## R-5. Распознавание формата и причины отказа

**Decision**: формат определяется по первым байтам, а не по расширению:

| Признак | Причина в отчёте |
|---|---|
| имя начинается с `.` | скрытый или служебный файл |
| папка `originals` или `reports` папки данных (при обходе) | служебная папка программы не обходится |
| размер 0 | пустой файл |
| `%PDF-` в первых 1024 байтах | PDF → открывается дальше |
| `D0 CF 11 E0` (DOC), `PK\x03\x04` + `.docx` / `word/` (DOCX) | формат не поддерживается: документ Word — сохраните его в PDF |
| `FF D8 FF` (JPEG), `89 50 4E 47` (PNG), `II*\0` / `MM\0*` (TIFF) | формат не поддерживается: изображение — сохраните документ в PDF |
| иное | формат не поддерживается |
| PDFium: ошибка пароля | защищён паролем |
| PDFium: иная ошибка открытия или ошибка при загрузке любой страницы | файл повреждён или не читается |
| 0 страниц | в файле нет страниц |

PDF, который открывается с пустым паролем пользователя (только ограничения владельца),
принимается: его текст читается.

**Rationale**: FR-002 и крайние случаи; каждый входной файл попадает ровно в одну группу
отчёта (FR-009), в том числе служебные файлы вроде `.DS_Store`.

## R-6. Доступ к базе и миграции

**Decision**: `psycopg` 3 (`psycopg[binary]`), SQL без ORM. Схема — нумерованные
SQL-файлы в пакете (`migrations/0001_intake.sql`), применяются командой `docreader migrate`
и учитываются в таблице `schema_migrations`. Остальные команды проверяют, что схема
актуальна, и иначе просят выполнить `migrate`.

**Rationale**: принцип VIII — четыре таблицы не оправдывают ORM и Alembic; простой
исполнитель миграций — несколько десятков строк.

**Alternatives considered**: SQLAlchemy + Alembic (лишний слой); автоприменение миграций
при каждом запуске (неявное изменение базы).

**Установка PostgreSQL** (в tech-context не указано, как запускать): PostgreSQL 17 +
`pgvector` на обеих машинах — на ноутбуке Homebrew `postgresql@17`, на сервере
разработки (Ubuntu 24.04, где штатно идёт 16) — пакеты PGDG, чтобы версии совпадали;
подключение через Unix-сокет или `localhost`. Расширение
`vector` в этой фиче не создаётся — его создаст миграция фичи 07. **[проверить]** установку
pgvector на ноутбуке до фичи 07.

**Защита принципа I**: адрес базы с хостом, отличным от Unix-сокета, `localhost`,
`127.0.0.1`, `::1`, отклоняется при запуске.

## R-7. Командная строка

**Decision**: стандартный `argparse`, команда `docreader` (точка входа в `pyproject.toml`,
также `python -m docreader`). Подкоманды: `migrate`, `add`, `list`, `show`, `remove`,
`verify`, `reclassify`, `page-kinds-check`. Человекочитаемый вывод на русском; у `add`,
`list`, `show` есть `--json` (для тестов и последующих фич).

**Rationale**: восемь подкоманд с простыми аргументами — задача на несколько десятков
строк (принцип VIII), отдельная библиотека не нужна. Сверх ориентира из части B добавлены:
`migrate` (R-6), `verify` (проверка SC-003 и FR-004), `reclassify` и `page-kinds-check`
(подбор порогов SC-004, R-2).

**Alternatives considered**: Typer / Click — удобнее, но лишняя зависимость.

## R-8. Настройки

**Decision**:
- `DOCREADER_DATA_DIR` — обязательная переменная окружения, без значения по умолчанию
  (чтобы данные не оказались случайно в рабочей папке агента). Команда отказывается
  работать, если папка данных лежит внутри репозитория.
- `DOCREADER_DATABASE_URL` — по умолчанию `postgresql:///docreader`.
- Необязательный `$DOCREADER_DATA_DIR/settings.toml` (читается стандартным `tomllib`)
  с порогами: `page_kinds.text_min_chars`, `page_kinds.full_image_coverage`,
  `intake.large_file_pages` (по умолчанию 200 — из Assumptions спецификации).
- Фактически применённые значения записываются в `run.settings` (принцип VI).

## R-10. Синтетические PDF для тестов

**Decision**: тестовые PDF создаются кодом во время тестов (фикстура pytest), бинарные
файлы в репозиторий не кладутся. Генератор — `reportlab` + `Pillow` (только dev-зависимости):
цифровой PDF; PDF из картинок на всю страницу; смешанный (текстовые страницы + страница-
картинка); картинка на всю страницу + невидимый текст (режим 3); картинка, нарезанная
полосами; страница с маленьким логотипом и текстом; пустая страница; зашифрованный PDF;
обрезанный (повреждённый) файл; файл нулевого размера; PDF без страниц (собирается
вручную минимальной структурой); «DOCX», «JPEG», «PNG» по сигнатурам.

**Rationale**: часть B требует именно эти синтетические файлы; реальные договоры в тесты
не попадают (принцип I). У `pypdfium2` нет шифрования PDF, поэтому генерация вынесена
в отдельную dev-зависимость. Текст синтетики — латиница: кириллица для фичи 01 не нужна,
а встроенные шрифты reportlab её не содержат (кириллический шрифт понадобится фиче 03).

**Тестовая база**: интеграционные тесты требуют `DOCREADER_TEST_DATABASE_URL` с правом
создавать базы; фикстура создаёт временную базу, применяет миграции и удаляет её. Если
переменная не задана, интеграционные тесты завершаются ошибкой с понятным сообщением,
а не пропускаются молча.
