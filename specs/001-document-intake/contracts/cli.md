# Contract: командная строка `docreader` (фича 01)

**Дата**: 2026-11-16 · **План**: [../plan.md](../plan.md) · **Модель данных**: [../data-model.md](../data-model.md)

Одна команда с подкомандами (tech-context). Запуск: `docreader <подкоманда>` или
`uv run docreader <подкоманда>` / `python -m docreader <подкоманда>`.

## Окружение

| Переменная | Обязательна | По умолчанию | Смысл |
|---|---|---|---|
| `DOCREADER_DATA_DIR` | да | — | папка данных вне репозитория: `originals/`, `reports/`, `settings.toml` |
| `DOCREADER_DATABASE_URL` | нет | `postgresql:///docreader` | только Unix-сокет или `localhost` / `127.0.0.1` / `::1` |

Необязательный `$DOCREADER_DATA_DIR/settings.toml`:

```toml
[page_kinds]
text_min_chars = 20          # не меньше стольких непробельных символов — «есть текст»
full_image_coverage = 0.85   # доля площади под изображениями — «изображение на всю страницу»

[intake]
large_file_pages = 200       # больше — предупреждение о размере
```

Неизвестный ключ или значение вне допустимого диапазона — ошибка окружения (код 2).

## Коды завершения

| Код | Когда |
|---|---|
| 0 | команда выполнена (у `add` — даже если часть файлов не добавлена: они в отчёте) |
| 1 | ошибка пользователя: путь не существует, идентификатор не найден, удаление не подтверждено, у `page-kinds-check` точность ниже 95% |
| 2 | ошибка окружения: не задана/недопустима папка данных, база недоступна или не локальна, схема не обновлена, ошибка в `settings.toml` |
| 130 | прервано (Ctrl-C); уже добавленные документы остаются |

Сообщения об ошибках — в stderr, на русском, одной строкой с подсказкой, что делать.

## Идентификатор на входе

`D-0001`, `d-0001`, `D-1` — одно и то же. Вывод всегда в каноническом виде `D-0001`.

## `docreader migrate`

Применяет неприменённые миграции. Повторный запуск — ничего не делает. Остальные команды
при устаревшей схеме завершаются с кодом 2 и советом выполнить `migrate`.

## `docreader add <путь>... [--note ТЕКСТ] [--label МЕТКА] [--json]`

- `<путь>` — файл или папка; папки обходятся рекурсивно, по именам в алфавитном порядке;
  символические ссылки на папки не обходятся. Можно указать несколько путей.
- `--note` — заметка, записывается каждому добавленному документу.
- `--label` — метка запуска (`run.label`).
- Создаёт одну запись `run` (`stage = 'intake'`, `settings.command = 'add'`).
- Каждый файл обрабатывается отдельно и атомарно.
- Отчёт печатается в stdout и сохраняется в `$DOCREADER_DATA_DIR/reports/intake-<run_id>.json`.

**Группы отчёта** (каждый входной файл ровно в одной):

| Группа | `status` в JSON | Данные |
|---|---|---|
| добавлен | `added` | идентификатор, число страниц, число страниц каждого вида |
| уже есть | `existing` | идентификатор существующего документа |
| не добавлен | `rejected` | причина (таблица причин — research R-5) |

**Предупреждения** (дополнительно к группе `added`):

| `code` | Текст |
|---|---|
| `scan_pages` | страницы-сканы на первом этапе не читаются: стр. 3, 7 |
| `scan_with_text_pages` | текст стр. 1–12 получен распознаванием и может содержать ошибки |
| `name_collision` | имя совпадает с D-0003 (другое содержимое) |
| `large_file` | 412 страниц — больше 200 |

**Пример текстового вывода**

```
Запуск 7, 2026-11-16 10:42, версия a1b2c3d

Добавлено: 3
  D-0006  dogovor_12.pdf        24 стр.  текст 24
  D-0007  dogovor_13.pdf        18 стр.  текст 17, скан 1
          ! страницы-сканы на первом этапе не читаются: стр. 18
  D-0008  scan_14.pdf            9 стр.  скан с текстом 9
          ! текст стр. 1–9 получен распознаванием и может содержать ошибки
Уже есть: 1
  dogovor_12_copy.pdf  → D-0006
Не добавлено: 2

  secret.pdf           защищён паролем

```

```json

  "run_id": 7,
  "started_at": "2026-11-16T10:42:05+05:00",
  "finished_at": "2026-11-16T10:42:08+05:00",
  "code_version": "a1b2c3d",
  "files": [
    {
      "path": "/Users/a/in/dogovor_13.pdf",
      "status": "added",
      "document_id": "D-0007",

      "page_kinds": {"text": 17, "scan": 1, "scan_with_text": 0},
```

`reason_code`: `hidden`, `empty`, `unsupported`, `word`, `image`, `encrypted`, `damaged`,
`no_pages`, `changed_during_add`.

## `docreader list [--json]`

Таблица всех документов по возрастанию идентификатора:

```
ID      Имя                     Стр.  Текст  Скан  Скан+т  Чтение   Структура Извлеч.  Проверки Индекс.
D-0001  dogovor_01.pdf            24     24     0       0  ожидает  ожидает   ожидает  ожидает  ожидает
```

Имя длиннее 40 символов обрезается с «…» (в `--json` — полностью). Пустой реестр —
строка «Реестр пуст», код 0.

JSON: массив объектов `{id, original_name, page_count, added_at, page_kinds{...},
stages{reading: {state, reason}, ...}}`.

## `docreader show <ID> [--json]`

Те же данные, что в `list`, плюс: отпечаток SHA-256, абсолютный путь к копии (SC-006),
исходный путь, размер, дата добавления, заметка, запуск добавления, причины состояний,
и по каждой странице — номер, вид, `char_count`, `image_coverage`, `invisible_text_share`.

## `docreader remove <ID> [--yes]`

1. Печатает, что будет удалено: идентификатор, имя, число страниц, путь к копии.
2. Просит ввести идентификатор для подтверждения. Ввод, не совпавший с идентификатором,
   или пустой ввод — «Удаление отменено», код 1, ничего не изменено.
3. `--yes` — без вопроса. Если stdin не терминал и нет `--yes` — отказ, код 1.
4. Одна транзакция: запись в `deletion_log` и `DELETE FROM document` (каскад на страницы,
   состояния и результаты последующих фич). После фиксации удаляется файл копии;
   ошибка удаления файла — предупреждение (код 0), файл остаётся и будет переиспользован
   при повторном добавлении того же содержимого.

## `docreader verify [<ID>...]`

Пересчитывает SHA-256 копий (всех или указанных) и сравнивает с `document.sha256`.
Вывод: «Копии в порядке: N» или список несовпавших / отсутствующих. Есть расхождение —
код 1. Запуск не создаёт.

## `docreader reclassify [<ID>...] [--label МЕТКА]`

Пересчитывает вид страниц по сохранённым показателям и текущим порогам из
`settings.toml`, без повторного открытия файлов. Создаёт запуск
(`stage = 'intake'`, `settings.command = 'reclassify'`). Для документов, у которых
изменился вид хотя бы одной страницы, все состояния этапов сбрасываются в «ожидает».
Вывод: сколько страниц изменили вид, по документам.

## `docreader page-kinds-check <labels.csv>`

Сверяет сохранённые виды страниц с ручной разметкой (SC-004). CSV в UTF-8 с заголовком:

```
document_id,page_number,kind
D-0001,1,text
D-0001,18,scan
```

`kind` — `text` / `scan` / `scan_with_text`. Вывод: число страниц, точность, матрица
ошибок 3×3, список несовпавших страниц с их показателями. Точность ниже 95% — код 1.
Строки с неизвестным документом или страницей — ошибка с номером строки, код 1.
Файл разметки содержит сведения о реальных договорах и хранится в папке данных.
