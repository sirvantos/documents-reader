# CLI: нарезка и индексы (фича 07)

Команды устроены по образцу `parse` и `extract` ([фича 05](../../005-field-extraction/contracts/cli.md)):
переменные окружения, `--json`, коды выхода (0 — успех, 1 — ошибка пользователя,
2 — ошибка окружения, 130 — прервано) те же. Решения — в [research.md](../research.md).

## `docreader index [ID…] [--all] [--label МЕТКА] [--json]`

Нарезает разобранные договоры на отрывки и строит оба индекса.

- Без аргументов — доступные договоры, у которых этап `indexing` в `pending` или
  `failed`, или отрывки построены по другому запуску разбора (R-7). `--all` — все
  доступные. `ID…` — указанные; `--all` вместе с ID — ошибка пользователя.
- Доступен договор, у которого разбор `done` или `needs_review` и получен по текущему
  тексту. Указанный недоступный договор не трогается и попадает в вывод со строкой
  «пропущен» и причиной («не разобран — выполните docreader parse D-0003»; «разбор
  устарел — выполните docreader parse D-0003»).
- Нечего строить — «Нечего индексировать: индексы всех договоров построены (заново:
  docreader index --all)», код 0.
- До первого договора проверяется сервер модели поиска. Нет ответа — «Модель поиска
  недоступна по адресу http://127.0.0.1:8081/v1 — запустите сервер модели поиска»,
  код 2, ни один договор не тронут. Так же при `DOCREADER_FORBID_MODELS` («На этой
  машине модель поиска не запускается (DOCREADER_FORBID_MODELS)»).
- Обрыв или тайм-аут на договоре — команда останавливается (код 2): текущий договор
  не тронут, уже построенные остаются; строка «Остановлено на D-0004: модель поиска
  не ответила (тайм-аут 120 с)».

Текстовый вывод — строка на договор и итог; ни меток, ни текста договоров (FR-011):

```text
D-0001  готово             отрывков 118, по словам 118, по смыслу 118
D-0002  требует просмотра  отрывков 120, по словам 120, по смыслу 120 — отрывок длиннее предела модели: D-0002/7.4
D-0003  пропущен           не разобран — выполните docreader parse D-0003
D-0004  ошибка             ошибка построения векторов: EmbeddingRequestError
Итого: готово 1, требует просмотра 1, ошибок 1, пропущено 1; отрывков 238 (запуск 72, модель bge-m3, размерность 1024)
```

`--json`:

```json
{
  "run_id": 72,
  "model": "bge-m3",
  "served_model": "bge-m3-Q8_0.gguf",
  "dims": 1024,
  "documents": [
    {"document_id": "D-0001", "state": "done", "reason": null,
     "passages": 118, "word_entries": 118, "vectors": 118, "truncated": 0,
     "seconds": 14.2}
  ],
  "skipped": [{"document_id": "D-0003", "reason": "не разобран — выполните docreader parse D-0003"}],
  "totals": {"indexed": 1, "needs_review": 1, "failed": 1, "skipped": 1, "passages": 238},
  "interrupted": false,
  "stopped": null
}
```

`stopped` — `null` или `{"document_id", "reason"}` при остановке из-за модели.
Вывод можно присылать агенту.

## `docreader passage D-0001/5.2 [--json]`

Один отрывок по идентификатору пункта (FR-012). Содержит текст договора: на реальных
договорах агенту не присылается.

```text
D-0001/5.2 — стр. 3–4, основной текст (индексация: запуск 72, 2026-11-25)
Метка: D-0001 · раздел 5. Ответственность сторон · пункт 5.2
В индексе по словам: да
В индексе по смыслу: bge-m3, размерность 1024
Текст:
5.2. За нарушение срока выполнения работ Подрядчик уплачивает неустойку …
```

Обрезанный вход — строка «В индексе по смыслу: bge-m3, размерность 1024 (вход обрезан
до 16000 знаков)».

Ошибки (код 1): неверный вид идентификатора — сообщение с примером (`parse_clause_id`);
неизвестный документ; «Отрывков нет: выполните docreader index D-0001»; «Нет отрывка
D-0001/5: у записи нет текста, кроме заголовка» (раздел только с заголовком) или
«Нет записи D-0001/9.9»; «Отрывки устарели: текст или разбор изменились — выполните
docreader index D-0001».

`--json`: `{"clause_id", "document_id", "clause_key", "part", "first_page", "last_page",
"label", "text", "word_index": true, "vectors": [{"model", "dims", "truncated",
"input_chars"}], "run_id"}`.
