## R-1. Интерфейс модели поиска по смыслу

**Decision.** К модели обращается только `docreader/embedding.py` — функция «тексты →
векторы» (tech-context, «Модели в автотестах») поверх локального OpenAI-совместимого
адреса `/v1/embeddings` и уже установленного клиента `openai` с HTTP-транспортом
`httpx2`, как `llm.py` фичи 05:

- `load_embedder(settings, transport=None) -> Embedder`; при `DOCREADER_FORBID_MODELS`
  без подменённого транспорта — `EnvironmentProblem` до создания клиента (общая
  константа `docreader/guards.py`); адрес `[embedding] base_url` — только петлевой
  (`config.is_local_model_url`); сетевые повторы SDK выключены, `OPENAI_*` окружения
  не читаются;
- `Embedder.check() -> EmbedderInfo(served_model, dims)` — пробный вектор на строке
  «проверка»; недоступен — `ModelUnavailable` (сообщение об окружении, код 2);
- `Embedder.embed(texts) -> list[list[float]]` пачками по `batch_size`; ответ должен
  содержать столько векторов, сколько текстов, одной длины `dims`, иначе
  `EmbeddingRequestError`; векторы нормируются (длина 1) в коде, чтобы косинус
  и скалярное произведение совпадали при любом сервере;
- обрыв соединения и тайм-аут → `ModelUnavailable` (остановка команды); ответ 4xx/5xx
  или не по форме → `EmbeddingRequestError` (ошибка одного договора).

Сервер на ноутбуке — `llama-server` из llama.cpp с BGE-M3 в формате GGUF:
`--embedding --pooling cls -c 8192 -b 8192 -ub 8192 -np 1 --host 127.0.0.1`. Модель и способ запуска
проверены 2026-11-24 (quickstart Б0–Б1): llama.cpp build 12359 (`b1b770d90`), веса
Q8_0, размерность 1024, `tests/real_model/test_embedding_server.py` — 5 из 5. Без
`-b 8192` логическая пачка 2048 урезает `-ub`, и вход в 4717 токенов получает HTTP 500.
Одинаковый текст даёт одинаковый вектор с точностью до округления на GPU (до 6·10⁻⁵ на
компоненту): тест сравнивает с допуском 10⁻³ и косинусом ≥ 0,9999.

**Rationale.** Принцип VIII: новой библиотеки нет (`openai`, `httpx2` пришли с фичей 05);
код не знает, чем запущена модель (tech-context, «OpenAI-совместимый интерфейс»), и BGE-M3
можно сменить на FRIDA или другой сервер без изменения кода. Защиты и подделки — те же,
что у языковой модели, их уже проверяют тесты.

**Alternatives considered.** `sentence-transformers`/`FlagEmbedding` в процессе:
PyTorch на несколько гигабайт, скачивание весов и телеметрия Hugging Face, сборки
под обе платформы — отклонено (VIII, I). Ollama `bge-m3`: тот же адрес подходит, но
это ещё одна служба с проверками обновлений; можно подставить без изменения кода.
`mlx-embeddings`: молодая библиотека, только macOS.

## R-2. Подделки модели в автотестах

**Decision.** `tests/fakes/embedding.py`, транспорт `httpx2.MockTransport`:

- `HashEmbedder(dims=8)` — вектор от SHA-256 входного текста (детерминированный, без
  сети, порядок результатов не важен — tech-context, «Векторы в тестах поиска»); хранит
  принятые тексты (`.inputs`) для проверок «что ушло в модель»;
- `FailingEmbedder(fail_on=…, kind="http_500" | "wrong_count" | "connect")` — ошибка
  на пачке, где есть текст с подстрокой `fail_on`;
- `DownEmbedder()` — любой запрос обрывается (сервер не запущен);
- фикстура `use_embedder` в `tests/conftest.py`, как `use_model` фичи 05.

Записей ответов (уровень 2) у фичи нет: векторы реальной модели нужны только для
качества поиска, а оно проверяется замерами фичи 08. Уровень 3 —
`tests/real_model/test_embedding_server.py` (только Mac): `check()`, размерность,
одинаковый вектор на одинаковый текст, длина 1, пачка из 16 текстов, вход ровно
в `max_chars` знаков принимается сервером, выключенный сервер — `ModelUnavailable`.
То, что тексты длиннее `max_chars` не уходят на сервер, проверяет модульный тест.

## R-3. Правило нарезки

**Decision.** Чистая функция `passages.cut(text, records, tail_end) -> list[PassageSpan]`
(`docreader/passages.py`) по записям `clause` документа в порядке `ordinal`:

| Запись | Отрывок |
|---|---|
| `preamble` | собственный текст целиком |
| `section` | собственный текст после первой строки (строки заголовка); пусто — отрывка нет |
| `clause` любой глубины | собственный текст целиком |
| `tail` | от начала хвоста до первой строки «Приложение» (`extraction_text.shown_end`, одно правило с фичей 05); строки нет — хвост целиком |

Границы обрезаются по пробельным символам с обеих сторон; отрывок, в котором после
обрезки ничего нет, не создаётся. Отрывок хранит место (`start`, `end_` в
`document_text.text`), а не копию текста (как `clause`); первая и последняя страница —
по `text_span` для `start` и `end_ - 1`.

Инвариант (SC-001, тест на каждом синтетическом договоре и в quickstart Б4): каждый
непробельный символ собственного текста записей, кроме строк заголовков разделов
и приложений хвоста, лежит ровно в одном отрывке; отрывки не пересекаются.

**Rationale.** Спецификация FR-001, уточнение 2026-11-24 (хвост). Записи разбора
подряд покрывают весь текст (data-model фичи 04), поэтому отрывки по собственным
текстам не пересекаются по построению. Обзор v1: 7029 отрывков, 701 раздел только
с заголовком, без распознанного раздела 0.

## R-4. Метка

**Decision.** `passages.label(document_id, record) -> str`, части через « · »:

| Запись | Метка |
|---|---|
| преамбула | `D-0001 · преамбула` |
| хвост | `D-0001 · реквизиты` |
| раздел с текстом | `D-0001 · раздел 2. Цена договора` |
| пункт, подпункт | `D-0001 · раздел 5. Ответственность сторон · пункт 5.2.1` |
| пункт без раздела (`section_number` NULL) | `D-0001 · пункт 7.3` |

Номер пункта — ключ записи (`5.2.1`), заголовок раздела — `clause.section_title`
(пустой заголовок — только «раздел 5»). Обзор v1: метка до 89 знаков, медиана 61.
В модель и в индекс по словам идёт `label + "\n" + текст`.

## R-5. Индекс по словам

**Decision.** У отрывка хранится `lemmas` — метка и текст в словарных формах — и
вычисляемый столбец `tsv = to_tsvector('simple', lemmas)` с индексом GIN. Функция
`wordforms.lemmatize(text) -> str` (`docreader/wordforms.py`):

- слова — последовательности букв и цифр с внутренними `-`, `/`, `.`
  (`ДП-17/2026`, `5.2.1`); остальное — разделители;
- слово с цифрой сохраняется как есть (FR-004: номера договоров и пунктов);
- знак «№» — слово «номер», в тексте и в запросе (изменено фичей 08, задача T027:
  договоры пишут номер только знаком, вопросы спрашивают «номер»);
- остальные слова — строчными, «ё» → «е», словарная форма первого разбора `pymorphy3`
  (тот же анализатор, что `values.py`; загрузка один раз на процесс);
- результат — слова через пробел в порядке текста.

Номер в двух столбцах ведёт себя по-разному (находка анализа U1, решение аналитика
2026-11-24 — вариант «оставить `simple`»): в `lemmas` он одно слово (`ДП-17/2026`), а
разборщик PostgreSQL и в `simple`, и в `russian` режет его по `-` и `/`
(`to_tsvector('simple', 'дп-17/2026')` → `'дп' '-17' '/2026'`, проверено на PostgreSQL
17.12). Поэтому через `tsv` номер целиком находится (запрос режется так же), а кусок
номера («17/2026») — нет. Позиции и частоты слов в `tsv` сохраняются — `ts_rank`
и поиск фразы фичи 08 работают; поиск по куску номера, если замер фичи 08 покажет,
что он нужен, — по `lemmas` (BM25) или отдельным индексом фичи 08.

Ранжирование (встроенное `ts_rank` по `tsv` или BM25 в памяти по `lemmas`) выбирается
и измеряется в фиче 08 (tech-context, «Поиск по словам в PostgreSQL»): оба варианта
работают на сохранённых `lemmas`, перестраивать отрывки не придётся.

**Alternatives considered.** Конфигурация `russian` (Snowball) — основы слов, а не
словарные формы; отклонено (FR-004). `tsv` из целых слов `lemmas`
(`array_to_tsvector`) — номер целый и в `tsv`, но без позиций и частот слов `ts_rank`
почти не различает отрывки; отклонено (U1). Без `tsv` в фиче 07 — индекса по словам
нет вовсе, FR-004 не выполняется; отклонено (U1). Отдельная
таблица записей индекса по словам — лишняя сущность: одна строка отрывка — одна
запись индекса.

## R-6. Индекс по смыслу и хранение векторов

**Decision.** Таблица `passage_vector`: отрывок, модель, вектор pgvector без
фиксированной размерности (`vector`) и `dims` с проверкой `vector_dims(embedding) =
dims`, число знаков, ушедших в модель, признак обрезки, запуск. Вектор передаётся
текстом `'[0.1,…]'::vector` — без Python-пакета `pgvector` (VIII). Индекса ANN нет:
7 тыс. векторов, точный перебор — доли секунды; индекс решает фича 08 по замеру.

Предел: в модель уходит не больше `[embedding] max_chars` знаков (по умолчанию
16 000 — заведомо меньше 8192 токенов BGE-M3 и в пять раз больше самого длинного
отрывка обзора v1, около 3,4 тыс. знаков с меткой). Длиннее — в модель уходят первые
`max_chars` знаков, `truncated = true`, договор получает «требует просмотра»
(уточнение 2026-11-24). Обрезка — по знакам в коде, без токенизатора: сервер не
получает слишком длинный вход и не падает.

## R-7. Какие договоры берёт `index`, устаревание

**Decision.**

- Доступен договор, у которого `structure` в `done`/`needs_review`, записи разбора
  есть и все `clause.source_text_sha256 = document_text.text_sha256` (как `extract`).
- Без аргументов: доступные договоры, у которых `indexing` в `pending`/`failed` или
  отрывки построены по другому запуску разбора (`passage.structure_run_id` ≠ `run_id`
  записей `clause`). Явные ID и `--all` — доступные договоры из списка или все;
  недоступный → «пропущен» с причиной («не разобран — выполните docreader parse
  D-…», «разбор устарел — …»).
- Чтение при смене текста уже возвращает `indexing` в `pending` («текст изменён»,
  `stages.reset_later`); прежние отрывки остаются до перестроения, но `passage` и
  фича 08 считают их неактуальными: отпечаток текста или запуск разбора не совпадают
  (FR-007).

**Rationale.** FR-006, FR-007, US2-4. Повторный `parse` не сбрасывает поздние этапы
(фича 04), а ключи записей могут поменяться; сравнение запуска разбора ловит это без
изменения фичи 04 и без повторного извлечения полей. Отступление от буквы FR-006
(«ожидает» или «ошибка») — расширение по FR-007, записано в plan.md.

## R-8. Состояние, причина, запись

**Decision.** Для одного договора: загрузка текста, записей и строк → `cut` → метки
и `lemmas` → `embed` всех отрывков (вне транзакции, с замером секунд) → одна
транзакция: `stages.lock`, `DELETE FROM passage WHERE document_id = …` (векторы
удаляются каскадом), вставка отрывков и векторов, `stages.set_state`.

| Случай | Состояние | Причина |
|---|---|---|
| все векторы построены, обрезки нет | `done` | — |
| есть обрезанный вход | `needs_review` | «отрывок длиннее предела модели: D-0001/5.2, D-0001/реквизиты» (до 5 идентификаторов и «и ещё N») |
| отрывков нет (нет собственного текста) | `needs_review` | «нет отрывков» |
| `EmbeddingRequestError` или иное исключение на договоре | `failed` | «ошибка построения векторов: <тип>» / «ошибка индексации: <тип>» — без сообщения исключения (оно может цитировать текст) |
| `ModelUnavailable` до или во время | — | команда останавливается, код 2; построенные договоры остаются, текущий не тронут |

**Rationale.** FR-008, FR-009, принцип VII; устройство — как `extraction.py`
(R-9, R-10 фичи 05).

## R-9. Настройки `[embedding]`

**Decision.** `EmbeddingSettings` в `config.py`, раздел `[embedding]` `settings.toml`:
`base_url = "http://127.0.0.1:8081/v1"` (только петлевой), `model = "bge-m3"`,
`timeout_s = 120`, `batch_size = 16`, `max_chars = 16000`. В `run.settings` —
значения раздела и `served_model`, `dims` из `check()`; `run.model` — `model`
(FR-010). Неизвестный ключ раздела — ошибка настроек, как у других разделов.

## R-10. pgvector на обеих машинах и в Docker

**Decision.** Миграция `0006_passages.sql` начинается с `CREATE EXTENSION IF NOT EXISTS
vector`. Установка — до первой миграции, quickstart А0 и Б0 (проверено 2026-11-24):

- сервер разработки: пакет PGDG `postgresql-17-pgvector` 0.8.7; `trusted = f`, поэтому
  `postgres` выполнил `CREATE EXTENSION vector` в `template1`, новые базы получают его
  из шаблона;
- ноутбук: Homebrew `pgvector` собран только для `postgresql@18`/`@19`, поэтому
  pgvector 0.8.7 собран из исходников (`make PG_CONFIG=…/postgresql@17/bin/pg_config`);
  без него `migrate` сообщает об окружении (`FeatureNotSupported` → `EnvironmentProblem`);
- Docker: образ базы `pgvector/pgvector:pg17` вместо `postgres:17` в `compose.yaml`.

Если роль без прав суперпользователя не может создать расширение (pgvector не помечен
как доверенный — проверить `pg_available_extension_versions.trusted`), суперпользователь
один раз выполняет `CREATE EXTENSION vector` в `template1` и в рабочих базах: новые базы
тестов и `docreader_demo` получают его из шаблона, а `IF NOT EXISTS` в миграции ничего не
делает. Ошибка прав при `migrate` — `EnvironmentProblem` с этой командой в сообщении.

## R-11. Команды

**Decision.** `docreader index [ID…] [--all] [--label МЕТКА] [--json]` — нарезка и оба
индекса; `docreader passage D-0001/5.2 [--json]` — один отрывок. Формы вывода —

`passage`: отчёт вне минимальной версии, а одна подкоманда без `build` повторяет
`parse` и `extract`.

## R-12. Скорость и память

**Decision.** SC-004 (≤ 30 мин на 56 договоров) — quickstart Б4 на ноутбуке
**[проверить]**: 7 тыс. отрывков пачками по 16; ожидание — минуты. Память (решение
