## Summary

Подкоманда `docreader index` нарезает разобранный договор на отрывки — один на запись
разбора с собственным текстом: преамбула, раздел с текстом после заголовка, пункт,
подпункт и раздел реквизитов хвоста до первой строки «Приложение» (R-3). Отрывок
хранит место в очищенном тексте и страницы, а не копию текста; метка — идентификатор
документа, раздел и номер пункта (R-4). Индекс по словам — метка и текст в словарных
формах (`pymorphy3`, номера как есть) в столбце `lemmas` и вычисляемый `tsvector`
`simple` с индексом GIN (R-5). Индекс по смыслу — вектор BGE-M3 от локального
OpenAI-совместимого сервера `/v1/embeddings` через уже установленный клиент `openai`
(`docreader/embedding.py`, R-1), в таблице `passage_vector` с pgvector (R-6). Вход длиннее
`max_chars` обрезается, договор — «требует просмотра» (уточнение 2026-11-24). Запись —
одна транзакция на договор; `passage D-0001/5.2` показывает отрывок. В автотестах
модель подменяется HTTP-транспортом: `HashEmbedder` даёт векторы от хэша текста (R-2).

## Technical Context

**Language/Version**: Python 3.12 (tech-context: 3.11 или новее), окружение — `uv`

**Primary Dependencies**: новых Python-библиотек нет: `openai` и `httpx2` (фича 05) —
клиент модели поиска, `pymorphy3` с `pymorphy3-dicts-ru` — словарные формы,
`psycopg[binary]` 3. Новое вне Python: расширение PostgreSQL `pgvector` (решено
в tech-context, установка — R-10) и на ноутбуке `llama.cpp` (`llama-server`) с весами
BGE-M3 в GGUF (R-1).

**Storage**: PostgreSQL 17 + pgvector, локально; миграция `0006_passages.sql`: расширение
`vector`, таблицы `passage` и `passage_vector` ([data-model.md](data-model.md)). Этап
`indexing` в `stage_status` уже есть.

**Testing**: `pytest`, уровни tech-context. Модульные — правило нарезки и покрытие,
метка, словарные формы, предел и обрезка, состояние и причина, настройки `[embedding]`,
защиты `embedding.py`, вывод команд. Интеграционные — CLI на временной базе (pgvector):
приём → чтение → разбор → `index` → `passage` на синтетических договорах
с `HashEmbedder`/`FailingEmbedder`. Записей ответов (уровень 2) нет (R-2). `real_model` —
только Mac.

**Target Platform**: рабочие прогоны — macOS, Apple M3 Pro, без сети, сервер модели поиска
на `127.0.0.1`; разработка и автотесты — сервер разработки Ubuntu 24.04 x86_64 и Docker
(модели нет).

**Project Type**: CLI-приложение, один пакет (как в фичах 01, 03, 04, 05, 13).

**Performance Goals**: 56 договоров (около 7 тыс. отрывков) ≤ 30 мин на ноутбуке
(SC-004) — **[проверить]** в Б4 (R-12); нарезка и словарные формы — доли секунды
на договор.

**Constraints**: без сети, кроме локального сервера модели поиска (FR-009; адрес только
петлевой); модель не запускается на сервере разработки (`DOCREADER_FORBID_MODELS`);
в модель не больше `max_chars` знаков на отрывок; одна транзакция записи на договор,
запросы к модели — вне транзакции; вывод `index` без текста договоров (FR-011).

**Scale/Scope**: 56 договоров, 7029 отрывков по обзору v1; 2 новые подкоманды, 2 таблицы,
1 раздел настроек, 1 модуль модели, 1 скрипт quickstart.

Неясностей (NEEDS CLARIFICATION) нет: вопросы спецификации закрыты уточнениями
2026-11-24, решения плана — в [research.md](research.md). Открыто только то, что
проверяется при установке и на ноутбуке: права на расширение pgvector (R-10), сервер
модели поиска и сжатие весов (R-1), скорость и память трёх моделей (R-12) — помечено
**[проверить]** в quickstart.

## Тесты

Модульные (каждый случай — отдельный тест):

- нарезка: по отрывку на преамбулу, пункт, подпункт; раздел только с заголовком — нет
  отрывка; раздел с текстом после заголовка — отрывок без строки заголовка; хвост —
  до строки «Приложение»; хвост без «Приложение» — целиком; пустой после обрезки —
  нет отрывка; границы без пробелов по краям; покрытие SC-001 и отсутствие пересечений
  на списке записей;
- метка: каждый вид R-4; пустой заголовок раздела; пункт без раздела;
- словарные формы: «неустойки», «неустойку» → «неустойка»; «ДП-17/2026», «5.2.1» —
  как есть; «ё»; регистр; знаки препинания; пустой текст;
- обрезка: вход ровно `max_chars` и на знак длиннее; несколько обрезанных — порядок
  и «и ещё N» в причине; состояние `done`/`needs_review`/`failed` по таблице R-8; в причине
  нет текста;
- `embedding.py`: FORBID без транспорта → `EnvironmentProblem` без сокетов; не петлевой
  адрес; пачки по `batch_size`; порядок по `index`; число и длина векторов; 500 →
  `EmbeddingRequestError`; обрыв и тайм-аут → `ModelUnavailable`; нормировка; текст
  длиннее `max_chars` → `ValueError`; сообщение без входного текста;
- настройки `[embedding]`: значения по умолчанию, неизвестный ключ, не петлевой адрес.

Интеграционные (CLI, временная база с pgvector, синтетические договоры):

- `index` без аргументов, с ID, `--all`; не разобранный и устаревший разбор — «пропущен»;
  отрывков столько, сколько записей с текстом; записи обоих индексов равны отрывкам;
  повторный запуск не меняет числа (SC-003); повторный `parse` → без аргументов
  договор берётся снова (R-7); удаление документа убирает отрывки и векторы (US2-5);
- то, что ушло в модель (`HashEmbedder.inputs`): метка и текст; текст отрывка в базе
  равен очищенному тексту по месту (SC-002); `tsv` находит «неустойка» по «неустойку»;
- состояния `done`, `needs_review` (низкий `max_chars` в `settings.toml`), `failed`
  (`FailingEmbedder`), следующий договор обрабатывается; модель недоступна до начала —
  код 2, ничего не тронуто; обрыв на втором договоре — первый записан, второй
  не тронут, код 2; FORBID — код 2;
- `passage`: вывод и `--json`, раздел только с заголовком, неизвестная запись,
  нет отрывков, устарели после смены текста и после повторного разбора; вывод `index`
  не содержит меток и текста (проверка по тексту синтетического договора).
