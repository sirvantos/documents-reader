# CLI: ответ по таблице (фича 10)

Как у `ask` ([фича 09](../../008-text-answers/contracts/cli.md)): переменные окружения,
`--json`, коды выхода (0 — ответ выведен, 1 — ошибка пользователя или ошибка ответа
модели, 2 — ошибка окружения, 130 — прервано). Решения — [research.md](../research.md).

## `docreader ask-table "ВОПРОС" [--include-unreviewed] [--json]`

Переводит вопрос в запрос языковой моделью, проверяет запрос и выполняет его по всем
договорам реестра по действующим значениям фичи 06. Ничего не пишет в базу.

- `--include-unreviewed` — учитывать и значения «требует просмотра» с найденным
  значением; ответ помечен «включает непроверенные значения», такие договоры отмечены.
  «Отклонено» не учитывается никогда.

| Случай | Сообщение | Код |
|---|---|---|
| пустой вопрос | «Пустой вопрос — введите вопрос о договорах» | 1 |
| в реестре нет договоров с извлечёнными полями | «По таблице ответить нельзя: нет извлечённых полей (docreader extract, docreader check)» | 1 |
| языковая модель недоступна / FORBID / адрес не петлевой | как у `extract` (фича 05) | 2 |
| обрыв или тайм-аут вызова модели | как у `extract` | 2 |
| ответ не по форме после повторов / HTTP-ошибка сервера модели | итог `failed`: «Ошибка ответа модели: …» | 1 |
| запрос недопустим и после повтора | итог `rejected`: «Запрос модели недопустим: <причина>» | 1 |
| отказ, уточнение, не поддерживается | итог `refused` / `clarify` / `unsupported` с причиной | 0 |

Сообщения об ошибках и предупреждения не содержат текста вопроса и значений договоров.
Сам вывод ответа содержит значения (наименования, номера, суммы): на реальных договорах
агенту отправляется только первая строка.

### Текстовый вывод (образец формы, синтетические значения)

```text
По таблице — ответ: 2 договора; учтено 8 из 9, не учтено 1; повторов 0; 4,2 с

Условие: подрядчик — ООО "Альфа"
Совпали наименования: ООО "Альфа", общество с ограниченной ответственностью "Альфа"

Договоры (2):
  D-0003  № 12/24-П   заказчик АО "Бета"   подрядчик ООО "Альфа"   без НДС 1 000 000,00   с НДС 1 200 000,00   окончание 2026-03-31   (D-0003/1)
  D-0007  № 7-ПД      заказчик АО "Бета"   подрядчик ООО "Альфа"   без НДС 250 000,00     с НДС —, требует просмотра   окончание 2025-12-31   (D-0007/преамбула)

Не учтено (1): требует просмотра 1 — D-0005

Получено: код 1d241f9; модель qwen3.6-27b-4bit, подсказка 10.2; правила 06.1; сегодня 2026-11-28
```

- Пункт в скобках — пункт значения поля условия.
- Значение, которое не действующее, показано со своим состоянием: найденное значение
  «требует просмотра» — само значение с пометкой; у остальных состояний значения нет —
  «—» и состояние.
- Причины в «Не учтено» — состояния ячейки поля условия (research R-5): `unreviewed` —
  «требует просмотра», `needs_review` — «требует просмотра, значения нет», `rejected` —
  «отклонено», `not_found` — «не найдено», `no_extraction` — «поля не извлечены»,
  `checks_stale` — «проверки не выполнены или устарели».
- С `--include-unreviewed` первая строка содержит «включает непроверенные значения»,
  у таких договоров в списке — «(непроверенное)».
- Строк больше `[table] list_rows`: «… ещё N — полный список: --json».
- Действие «посчитать»: вместо «Договоры (N):» — тот же список под заголовком
  «Из каких договоров (N):».
- Второй запрос в вопросе: строка «Выполнен первый запрос; не выполнено: <other>».
- Отказ: первая строка «По таблице — отказ; повторов 0; 3,1 с», затем «Причина: <reason>»
  и «Поиск по тексту не подставляется (docreader ask)».
- Уточнение и «не поддерживается»: первая строка «По таблице — нужно уточнение; повторов 0;
  3,1 с» / «По таблице — не поддерживается; повторов 0; 3,1 с», затем «Причина: <reason>».
- `reason` и `other` модели — перефраз вопроса: в первую строку они не попадают никогда
  (FR-014: первая строка — исход, числа, время).

### `--json`

Объект `TableAnswer.to_json()` ([data-model.md](../data-model.md)): `outcome`, `reason`,
`other`, `retried`, `today`, `seconds`, `provenance`, `result` (`query`, `count`,
`considered`, `include_unreviewed`, `matched_names`, `rows` — все, с ячейками шести
полей, `excluded` — по причинам).

## Скрипты замера (ноутбук аналитика)

### `uv run --env-file .env python scripts/make_table_questions.py [--force] [--seed 0]`

Вопросы по шаблонам из действующих значений с ожидаемым запросом (R-12) →
`$DOCREADER_DATA_DIR/questions/table-10.toml`. Печатает только числа вопросов по полям
и действиям.

### `uv run --env-file .env python scripts/quickstart_table.py [--questions FILE]`

Формат файла — список `[[question]]`: `text`, `source` (`template` | `analyst`) и одно
из двух: `expected = {action, field, op, value, value_to?}` или
`expected_outcome = "refused" | "clarify" | "unsupported"`; необязательно
`documents = ["D-0003", …]` (ожидаемый список). Печатает и сохраняет рядом с файлом
вопросов `table-b4-summary-….txt`: вопросов, верных (по шаблонам / аналитика), неверный
запрос, неверный исход, неверный список — по номерам вопросов; исходы; повторы; время
(медиана, наибольшее). Полные ответы — `table-b4-….txt`, только для аналитика.
