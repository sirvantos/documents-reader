## Summary

Подкоманда `docreader ask-table "ВОПРОС" [--include-unreviewed] [--json]` и функция
`table_answer.ask_table` для скрипта замера. Та же языковая модель, что в фичах 05 и 09
(`[extraction]`, `llm.py` без изменений), получает вопрос, сегодняшнюю дату и описание
шести полей — без значений таблицы — и возвращает форму `TableReply`: запрос (действие
«посчитать» или «перечислить», одно условие: поле, сравнение, значение) либо отказ,
просьбу уточнить или «не поддерживается» (подсказка 10.3, R-3). Программа проверяет
запрос (R-4; недопустимый — один повтор с причиной, R-9), загружает строки таблицы всех
договоров по действующему значению фичи 06 (R-5), выполняет запрос чистой функцией
(сравнения сумм `Decimal`, дат ISO, номеров по приведённому виду, наименований — правилом
фичи 02 или по названию в кавычках; сторона при «договоры с X» — по таблице; R-7)
и собирает ответ по шаблонам: число, условие простыми словами, список договоров с шестью
полями и пунктом поля условия, неучтённые по причинам (R-8). Ничего не пишется в базу.
Замер — `scripts/make_table_questions.py` (вопросы по шаблонам с ожидаемым запросом)
и `scripts/quickstart_table.py` (сводка только числами, R-12). В автотестах —
`ScriptedModel`, записи реальной модели на синтетических вопросах, договоры
`make_check_contracts` фичи 06 (R-11).

## Technical Context

**Language/Version**: Python 3.12 (tech-context: 3.11 или новее), окружение — `uv`

**Primary Dependencies**: новых библиотек нет: `instructor` и `openai` через `llm.py`
(фича 05), `pydantic` (схема ответа), `psycopg[binary]` 3. Вне Python, на ноутбуке:
`mlx_lm.server` с `qwen3.6-27b-4bit` (как в фичах 05 и 09). Модели поиска и реранкер
не нужны.

**Storage**: PostgreSQL 17, только чтение таблиц фич 01, 05 и 06
([data-model.md](data-model.md)); миграции нет.

**Testing**: `pytest`, уровни tech-context. Модульные — `validate` (каждая причина),
периоды, сопоставление наименований и сторона, `execute` (каждое состояние ячейки,
каждое сравнение и граница), `describe`, текст ответа, подсказка и схема, повтор
(`ScriptedModel`), настройки `[table]`, скрипты замера. Интеграционные — CLI и функция
на временной базе: `make_check_contracts` → `extract` → `check` → `check load` →
`ask-table`. Уровень 2 — `tests/recordings/10-table-answers/`. Уровень 3 —
`test_table_server.py`, только Mac.

**Target Platform**: рабочие прогоны — macOS, Apple M3 Pro, без сети, модель на
`127.0.0.1`; разработка и автотесты — сервер разработки Ubuntu 24.04 x86_64 и Docker
(моделей нет).

**Project Type**: CLI-приложение, один пакет (как в прежних фичах).

**Performance Goals**: ответ ≤ 20 с, медиана по вопросам замера (SC-004) — не измерено:
один вызов модели с короткой подсказкой и `max_tokens` 512, выполнение по 56 договорам —
доли секунды; проверяется в Б4.

**Constraints**: без сети, кроме локальной модели (адрес только петлевой); модель
не запускается на сервере разработки (`DOCREADER_FORBID_MODELS`); проверки модели —
до вызова; ни одно сообщение об ошибке и предупреждение без текста вопроса и значений
договоров; первая строка вывода — без значений (FR-014); сводка замера — только числа
и идентификаторы.

**Scale/Scope**: 56 договоров, 6 полей; 1 подкоманда, 3 новых модуля (`table_prompt`,
`table_query`, `table_answer`), 1 раздел настроек, 2 скрипта замера, 1 команда записи;
без миграции.

Неясностей (NEEDS CLARIFICATION) нет: вопросы спецификации закрыты уточнениями
2026-11-27, решения плана — в [research.md](research.md). Открыто только то, что
проверяется на ноутбуке: форма ответа реальной модели (Б1, Б2), доля верных и скорость
(Б4).
