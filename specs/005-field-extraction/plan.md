## Summary

Подкоманда `docreader extract` заполняет у разобранного договора шесть полей прототипа
одним обращением к локальной языковой модели. Модель получает преамбулу, основной
текст и реквизиты — текст до первой строки «Приложение» в хвосте (R-4) — и по каждому
полю возвращает запись значения, дословную цитату и номер пункта или «не найдено»
(Instructor поверх OpenAI-совместимого клиента, режим `md_json`, до двух повторов;
R-1, R-3). Дальше — только обычный код: цитата ищется общей `textnorm.locate`
в показанной части, по её месту определяются пункт (запись `clause` фичи 04)
и страницы (R-5); значение приводится по виду каталога (сумма, дата, идентификатор,
наименование) и должно найтись в цитате (R-6, R-7). Итог поля — «найдено», «не
найдено», «отклонено» или «ошибка»; состояние договора и причина — по правилам R-8.
Результат — шесть строк `field_value` на договор в одной транзакции; `fields ID`
показывает их. В автотестах модель подменяется HTTP-транспортом: заглушки по сценарию
и ответы, записанные на ноутбуке с реальной модели на синтетических договорах (R-2).

## Technical Context

**Language/Version**: Python 3.12 (tech-context: 3.11 или новее), окружение — `uv`

**Primary Dependencies**: новые — `instructor` (MIT) и `openai` (Apache-2.0), с ними
`pydantic` и `httpx` (R-12); уже есть — `psycopg[binary]` 3, `pymorphy3` с
`pymorphy3-dicts-ru` (словарные формы наименований). Генератор синтетики — `reportlab`
и DejaVu Sans из `tests/synthetic/fonts/`.

**Storage**: PostgreSQL 17, локально; миграция `0005_extraction.sql`: таблица
`field_value` ([data-model.md](data-model.md)). Этап `extraction` в `stage_status`
уже есть.

**Testing**: `pytest`, уровни tech-context. Модульные — приведение и проверка значений,
поиск цитаты и пункт, состояние и причина, показанная часть, подсказка и схема,
настройки, защиты `llm.py`. Интеграционные — CLI на временной базе: приём → чтение →
разбор → `extract` → `fields` на синтетических договорах с `ScriptedModel` (уровень 1)
и `RecordedModel` (уровень 2). `real_model` — только Mac.

**Target Platform**: рабочие прогоны — macOS, Apple M3 Pro, без сети, сервер модели
на `127.0.0.1`; разработка и автотесты — сервер разработки Ubuntu 24.04 x86_64 и Docker
(модели нет).

**Project Type**: CLI-приложение, один пакет (как в фичах 01, 03, 04, 13).

**Performance Goals**: 56 договоров ≤ 8 ч на ноутбуке (SC-004, ≤ 8,5 мин на договор);
скорость модели не измерена — **[проверить]** в Б3 (R-13). Проверка цитат и запись —
доли секунды на договор.

**Constraints**: без сети, кроме локального сервера модели (FR-014; адрес только
петлевой); модель не запускается на сервере разработки (`DOCREADER_FORBID_MODELS`);
температура 0; одна транзакция записи на договор, запрос к модели — вне транзакции;
вывод `extract` без текста договора (FR-015); показанная часть ≤ `max_shown_chars`.

**Scale/Scope**: 56 договоров × 6 полей = 336 строк; 2 новые подкоманды, 1 таблица,
1 раздел настроек, 1 команда записи, 5 синтетических вариантов.

Неясностей (NEEDS CLARIFICATION) нет: вопросы спецификации закрыты уточнениями
2026-11-22, решения плана — в [research.md](research.md). Открыто только то, что

## Тесты

Модульные (каждый случай — отдельный тест):

- суммы: «64 270 348 (…) рублей 83 копейки» → `64270348.83`; без копеек → `.00`;
  `64 270 348,83 руб.`; значение модели `64270348.83`; число без «руб…» в цитате
  не считается суммой; неразбираемое → причина;
- даты: «25 марта 2026 г.», «"25" Марта 2026 года», `25.03.2026`, `2026-03-25`;
  `31.02.2026` → причина;
- номер: «№ ДП-17/2026» → `ДП-17/2026`; тире и латинские двойники; пробел внутри;
- наименование: со скобками и без; падеж («ООО «Альфа»» в «ООО «Альфы»»); «ё»;
  слово не по порядку → не подтверждено;
- цитата: через перенос строки (заголовок на двух строках); отличие пробелами, дефисом,
  кавычками, «ё» → найдена; нет в тексте; есть только в приложении → «цитата
  не найдена»; несколько вхождений — пункт модели, иначе первое; граница пунктов —
  пункт начала; цитата в хвосте → `реквизиты`; цитата на двух страницах;
- результат поля по таблице R-8 (каждая строка); лишние поля ответа отброшены;
- состояние и причина: done; not_found не меняет; rejected; низкое качество страницы
  цитаты; непрочитанная страница в показанной части и в приложении; порядок частей
  причины; нет текста договора в причине;
- показанная часть: «Приложение» в хвосте; «Приложения:» не граница; строка-ссылка
  на приложение в основном тексте не граница; нет хвоста; предел длины;
- подсказка: маркеры данных, все шесть полей в схеме, `PROMPT_VERSION` и
  `prompt_sha256` меняются вместе с текстом;
- `llm.py`: FORBID без транспорта → `EnvironmentProblem` без сокетов; не петлевой
  адрес; ответ не по форме → повтор → `AnswerFormError` после `max_retries`; тайм-аут
  и обрыв → `ModelUnavailable`; параметры запроса (температура, seed, extra_body);
- запись: путь вне `tests/synthetic/` и ссылка наружу — отказ до загрузки настроек;
  `RecordedModel` — устаревшая версия, другой отпечаток запроса → `StaleRecording`.

Интеграционные (CLI, временная база, синтетические договоры):

- `extract` без аргументов, с ID, `--all`; не разобранный / устаревший разбор —
  «пропущен»; шесть строк на договор; повторный запуск заменяет (US1-5);
- состояния `done`, `needs_review`, `failed` и причины; ответ не по форме одного
  договора не останавливает остальные; модель недоступна до начала — код 2, ничего
  не тронуто; обрыв на втором договоре — первый записан, второй не тронут, код 2;
- скан-случаи через поддельный движок фичи 13: низкое качество, непрочитанная
  страница в основном тексте и в приложении;
- `fields`: вид вывода, `--json`, не извлекались, устарели после смены текста;
  повторный `parse` того же текста не меняет `fields`; вывод `extract` не содержит
  значений и цитат (проверка по значениям варианта);
- уровень 2: варианты R-14 с `RecordedModel` дают результаты `truth.json` (SC-005).
