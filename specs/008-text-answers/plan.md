## Summary

Подкоманда `docreader ask "ВОПРОС" [--document ID]` и функция `answer.ask` для скрипта
замера. Отрывки находит `search.search` фичи 08 с настройками по умолчанию (слияние
и реранкер), модели показываются первые `[answer] passages` (8); при вопросе об одном
договоре к ним всегда добавляется его преамбула, если поиск её не нашёл (FR-010, R-5).
Та же языковая модель, что в фиче 05 (соединение `[extraction]`, `llm.py` без
изменений, R-2), возвращает вид ответа и утверждения с пунктом и цитатой (подсказка
09.1, R-3). Программа проверяет каждую цитату общей функцией `textnorm.locate` — сначала
в названном пункте, затем в остальных показанных отрывках, только в их границах (R-4);
при ненайденных — один повтор только для них, подтверждённые сохраняются (R-6). Текст
ответа собирает код из подтверждённых утверждений; итог — `answered`, `unconfirmed`,
`not_found` или `failed` (R-8). Ничего не пишется в базу (R-11). Замер —
`scripts/quickstart_answers.py` по файлу вопросов аналитика: полные ответы — в файл
для аналитика, сводка — только числа (R-10). В автотестах — `ScriptedModel`, записи
реальной модели на синтетике (`record_answers`) и подделки поиска фичи 08 (R-9).

## Technical Context

**Language/Version**: Python 3.12 (tech-context: 3.11 или новее), окружение — `uv`

**Primary Dependencies**: новых библиотек нет: `instructor` и `openai` через `llm.py`
(фича 05), `httpx2` (подделки), `pydantic` (схема ответа), `psycopg[binary]` 3. Вне

и с BGE Reranker v2-m3 — все три уже запускались вместе (tech-context, «Что проверить
в первый день», п. 3).

**Storage**: PostgreSQL 17 + pgvector, только чтение таблиц фич 03, 07 и 08
([data-model.md](data-model.md)); миграции нет.

**Testing**: `pytest`, уровни tech-context. Модульные — проверка цитаты (каждое правило
R-4), правило повтора (R-6), итог (R-8), схема и сообщения подсказки, преамбула (R-5),
настройки `[answer]`, вывод, скрипт замера. Интеграционные — CLI и функция на временной
базе: приём → чтение → разбор → `index` (`TopicEmbedder`) → `ask` (`TableReranker`,
`ScriptedModel`) на `make_answer_contracts`; уровень 2 — записи
`tests/recordings/09-text-answers/`. Уровень 3 — `test_answer_server.py`, только Mac.

**Target Platform**: рабочие прогоны — macOS, Apple M3 Pro, без сети, модели на
`127.0.0.1`; разработка и автотесты — сервер разработки Ubuntu 24.04 x86_64 и Docker
(моделей нет).

**Project Type**: CLI-приложение, один пакет (как в прежних фичах).

**Performance Goals**: ответ ≤ 60 с, медиана по вопросам замера (SC-004) — не измерено,
проверяется в Б4 (R-12).

**Constraints**: без сети, кроме локальных моделей (адреса только петлевые, FR-007);
модели не запускаются на сервере разработки (`DOCREADER_FORBID_MODELS`); проверки
области и моделей — до поиска и до модели (R-7); ни одно сообщение и предупреждение
без текста вопроса и договоров (FR-009); сводка замера — только числа (FR-012).

**Scale/Scope**: 56 договоров; 1 подкоманда, 3 новых модуля (`answer`, `answer_prompt`,
`answer_check`), 1 раздел настроек, 1 скрипт замера, 1 команда записи; без миграции.

Неясностей (NEEDS CLARIFICATION) нет: вопросы спецификации закрыты уточнениями
2026-11-25, решения плана — в [research.md](research.md). Открыто только то, что
проверяется на ноутбуке: форма ответа реальной модели (Б1, Б2) и скорость (R-12, Б4).

## Тесты

Модульные (каждый случай — отдельный тест):

- `check_claim`: цитата в названном пункте → `confirmed`; в другом показанном →
  `confirmed_elsewhere`, ссылка фактическая, названный пункт сохранён; в договоре, но
  вне показанных отрывков → `quote_not_found`; пересказ → `quote_not_found`; пустая →
  `no_quote`; через перенос строки и с другими пробелами, «ё», кавычками → найдена;
  на стыке двух отрывков → не найдена; формы пункта `D-0015/2.2`, `2.2`, `п. 2.2`,
  `2.2.`, `Преамбула`; чужой префикс договора → ищется в остальных; несколько
  вхождений — первое в названном; страницы — по `text_span`, цитата через страницу —
  две страницы;
- `merge_retry`: подтверждённые первого ответа не меняются и идут первыми; исправленное
  повтором добавляется; повтор не исправил — пометка; повтор `None`, `not_found`,
  пустой — пометка у утверждений первого ответа; дубль места не добавляется; числа
  `not_found_first`/`not_found_final`;
- итог: каждая строка таблицы R-8;
- `answer_prompt`: схема принимает оба вида, отклоняет `answer` без утверждений,
  `not_found` с утверждениями, больше 10; сообщения — отрывки с идентификаторами
  по порядку, фигурные скобки в тексте не ломают подстановку; повтор — прежние
  сообщения, ответ модели, номера неподтверждённых; отпечаток меняется с подсказкой;
- настройки `[answer]`: значения по умолчанию, неизвестный ключ, `passages >
  rerank_candidates`;
- вывод: каждый итог, исправленная ссылка, добавленная преамбула, `--json`;
- скрипт замера: итоги по пометкам, ошибка в наборе не входит в итог, повторная
  проверка цитат, в печати и сводке нет текста вопросов и договоров.

Интеграционные (CLI и функция, временная база, `make_answer_contracts`,
`use_embedder(TopicEmbedder)`, `use_reranker(TableReranker)`, `use_model(ScriptedModel)`):

- история 1: подтверждённый ответ со ссылкой и страницей; цитата в другом показанном
  пункте — ссылка исправлена; пересказанная цитата — повтор исправил / не исправил;
  `--document` — все отрывки и ссылки из договора (SC-002 — каждый случай); повторный
  вопрос — те же отрывки и тот же запрос к модели (`ScriptedModel.requests`);
- преамбула: `--document`, поиск её не нашёл (`--passages 2`, порядок `TableReranker`) —
  добавлена последней с отметкой, цитата из неё подтверждена; поиск её нашёл —
  не дублируется; договор без преамбулы — ничего не добавлено; без `--document` —
  не добавляется;
- история 2: модель вернула «не найдено» — итог и просмотренные пункты; ни одна
  цитата не найдена — `unconfirmed`; текст-указание в отрывке не меняет проверку;
- ошибки: пустой вопрос, неизвестный договор, устаревшие отрывки — код 1 до моделей
  (`ScriptedModel.requests` пуст); модель недоступна, FORBID — код 2; ответ не по форме
  после повторов, HTTP 400 — `failed`, код 1, просмотренные пункты выведены; повтор
  не по форме — итог первого ответа сохранён; сообщения без текста вопроса;
- уровень 2: варианты `payment`, `parties`, `absent` на записях.
