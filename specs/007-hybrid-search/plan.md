## Summary

Подкоманда `docreader search "ЗАПРОС"` и функция `search.search` для фичи 09 ищут
отрывки фичи 07 двумя способами: по словам — BM25 по сохранённым `lemmas` в коде (R-1;
запрос в тех же словарных формах, без служебных слов, R-2) и по смыслу — точный
перебор векторов `bge-m3` в PostgreSQL (R-3). Списки сливаются по местам (RRF, k = 60,
R-4); первые 30 пересортировывает реранкер BGE Reranker v2-m3 на локальном
`llama-server --reranking` (`docreader/reranker.py`, R-7), в результат идут 8. Реранкер
включён по умолчанию, `--no-rerank` его выключает; включённый и недоступный —
остановка с кодом 2. `--document D-…` ограничивает поиск одним договором (R-5). Ищутся
только актуальные отрывки, остальные договоры названы числом в предупреждении (R-6).
Поиск ничего не пишет в базу. Замер — `scripts/quickstart_search.py` на вопросах
аналитика: места правильного пункта без реранкера и с ним, время, решение по правилу
FR-014 (R-11). В автотестах обе модели подменены HTTP-транспортом: `TopicEmbedder`
и `TableReranker` (R-8).

## Technical Context

**Language/Version**: Python 3.12 (tech-context: 3.11 или новее), окружение — `uv`

**Primary Dependencies**: новых библиотек нет: `httpx2` (клиент реранкера), `openai`
(модель поиска, фича 07), `pymorphy3` (словарные формы запроса), `psycopg[binary]` 3.
Вне Python: на ноутбуке `llama-server` с весами BGE Reranker v2-m3 в GGUF (Q8_0, уже
скачаны и запускались в Б3 фичи 07).

**Storage**: PostgreSQL 17 + pgvector, только чтение таблиц фичи 07
([data-model.md](data-model.md)); миграции нет.

**Testing**: `pytest`, уровни tech-context. Модульные — BM25, служебные слова, слияние
и порядок равных, правило FR-014, вход реранкера и обрезка, защиты и разбор ответа
`reranker.py`, настройки `[search]`/`[reranker]`, вывод, скрипт замера. Интеграционные —
CLI и функция на временной базе: приём → чтение → разбор → `index` (подделки) →
`search` на синтетических договорах. Уровень 3 — `test_reranker_server.py`, только Mac.

**Target Platform**: рабочие прогоны — macOS, Apple M3 Pro, без сети, модели на
`127.0.0.1`; разработка и автотесты — сервер разработки Ubuntu 24.04 x86_64 и Docker
(моделей нет).

**Project Type**: CLI-приложение, один пакет (как в прежних фичах).

**Performance Goals**: медиана поиска ≤ 3 с без реранкера, ≤ 10 с с ним (SC-003) —
**[проверить]** в Б3 (R-12).

**Constraints**: без сети, кроме локальных моделей (FR-008, адреса только петлевые);
модели не запускаются на сервере разработки (`DOCREADER_FORBID_MODELS`); проверки
области и моделей — до поиска (FR-009); при включённом реранкере нет вывода без
пересортировки (FR-005); вывод замера без текста (FR-012).

**Scale/Scope**: 56 договоров, 7029 отрывков; 1 подкоманда, 1 модуль модели, 1 модуль
поиска, 2 раздела настроек, 1 скрипт замера; без миграции.

Неясностей (NEEDS CLARIFICATION) нет: вопросы спецификации закрыты уточнениями
2026-11-24, решения плана — в [research.md](research.md). Открыто только то, что
проверяется на ноутбуке: путь и форма ответа `/v1/rerank` (R-7, Б1), скорость (R-12, Б3).

## Тесты

Модульные (каждый случай — отдельный тест):

- BM25: редкое слово весит больше частого; длинный отрывок с тем же словом ниже
  короткого; слово с цифрами совпадает целиком («дп-17/2026»), кусок номера —
  нет; порядок равных — по договору и `ordinal`; пустой запрос → нет кандидатов;
- `query_terms`: «неустойки» → «неустойка»; «ДП-17/2026» как есть (нижний регистр);
  «и в на по» → пусто; повторы убраны;
- RRF: найденный обоими выше найденного одним на тех же местах; места с 1; `k`;
  равные; обрезка до `rerank_candidates`;
- `decide`: каждая строка правила FR-014, медиана ровно 10 с и 10,01 с, все вопросы —
  ошибки в наборе;
- `reranker.py`: FORBID без транспорта → `EnvironmentProblem` без сокетов; не петлевой
  адрес; порядок по `index`; число оценок ≠ n, повтор `index`, не число, не JSON,
  500 → `RerankRequestError`; обрыв и тайм-аут → `ModelUnavailable`; сообщения без
  входного текста; `rerank_input` — обрезка запроса и документа;
- настройки: значения по умолчанию, неизвестный ключ, `results > rerank_candidates`,
  не петлевой `base_url`.

Интеграционные (CLI и функция, временная база, синтетика, `use_embedder(TopicEmbedder)`
при `index` и `search`, `use_reranker(TableReranker)`):

- история 1: номер находится по словам, перефразированный пункт — по смыслу,
  словоформы; места по способам в `--json`; повторный поиск — тот же список (SC-004);
- история 2: `--document` — все результаты из договора (SC-002); без него типовой пункт
  трёх договоров — три результата; неизвестный договор, нет отрывков, устарели —
  код 1 и сообщения контракта;
- история 3: порядок по `TableReranker`, места до и после; `--no-rerank` —
  `TableReranker.requests` пуст; `DownReranker`, `FailingReranker` каждого вида —
  код 2, ни одной строки результата; FORBID при `enabled = true` — код 2;
- особые случаи: «и в на по» — кандидаты только по смыслу и предупреждение; запрос
  длиннее `max_chars` — предупреждение; устаревшие договоры — предупреждение с числом,
  их отрывков в результате нет; нет векторов выбранной модели — код 2; индексы пусты —
  код 1;
- скрипт замера на `search_questions.toml`: места, итог, решение; ошибка в наборе
  не входит в итог; в выводе нет текста вопросов и синтетических договоров.
