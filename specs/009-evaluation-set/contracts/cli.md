# Contract: команды `docreader eval`

Все команды требуют `DOCREADER_DATA_DIR` и базу (как остальные). Коды выхода — как
у прежних фич: 0 — сделано; 1 — ошибка пользователя или данных (причина на русском
с подсказкой); 2 — ошибка окружения (`EnvironmentProblem`: нет базы, модель
недоступна, `DOCREADER_FORBID_MODELS`). `--json` — то же самое в виде JSON (только
поля, перечисленные ниже, без значений и текста).

**Что можно присылать агенту.** Вывод в терминал всех команд `eval` на реальных
договорах можно присылать: в нём только числа, доли, идентификаторы документов,
пунктов, вопросов и записей, названия полей, исходы, причины и пути файлов (FR-026).
Файлы, пути к которым команды печатают (шаблоны, страница проверки и её ответы,
файлы разбора, сгенерированные вопросы, выгрузки), содержат значения и текст
договоров и **не присылаются никогда**.

Тест на каждую команду проверяет, что в выводе (обычном и `--json`) нет ни одного
значения эталона, системы или правил, ни одного текста вопроса и цитаты.

## Эталон полей

### `docreader eval template [--fields prototype|queue1|all] [--documents ID…] [--out ФАЙЛ]`

Пустой шаблон (contracts/files.md «Шаблон»). По умолчанию поля очереди 1, поля
прототипа первыми; документы — все документы реестра по порядку идентификаторов;
файл — `$DOCREADER_DATA_DIR/eval/template-<время>.csv` (поверх существующего не пишет).

```
Шаблон: eval/template-20261127-101500.csv
  документов 56, полей 35 (очередь 1; прототипа 6 — первыми)
  ячейки пусты; «отсутствует» — поля нет в договоре; варианты — через « || »
```

### `docreader eval review [ID…] [--out ПАПКА]`

Страница проверки шести полей прототипа (research R-9). Без ID — все документы
с результатами фичи 05.

```
Страница проверки: eval/review-20261127-102000/index.html
  карточек 336: изменилось 0, разошлось 21, только правила 2, никто 1, только модель 18, совпало 294
  уже с ответом из эталона: 0
  ждут слепой разметки (карточки не показаны): D-0004, D-0015, D-0027, D-0040, D-0052
  места для карточек без значения — только поиск по словам
```

Код 1: нет документов с результатами фичи 05; указанный документ без них.

### `docreader eval load ФАЙЛ [--yes]`

Загрузка ответов страницы (`.json`) или шаблона (`.csv`) в эталон по правилу замены
(research R-6).

```
Загрузка: ответы страницы проверки (336 карточек)
  принято 330: совпало 291, выбрано из двух 20, вписано 3, отсутствует 16; пропущено 6
  ошибок вида 1: карточка D-0012/amount_with_vat — значение не приводится к сумме
  в пределах файла: добавлено 330, изменено 0, убрано 0
  по полям: contract_number 55/56, customer_name_short 56/56, …
  версия эталона: 3f9c0a1b2d4e
```

Если убирается хотя бы одно значение без `--yes` — те же числа и строка
`убирается 4 значения: повторите с --yes, чтобы заменить`; код 1, эталон не меняется.

## Сравнение и таблица результатов

### `docreader eval fields [--label МЕТКА] [--source extraction|rules] [--from ФАЙЛ.json] [--fields prototype|queue1|all]`

Сравнение (research R-7). По умолчанию источник — результаты фичи 05, поля — все
размеченные. Пишет запись и файл разбора.

```
Сравнение полей: запись 8 «подсказка 05.1» (извлечение; подсказка 05.1, qwen3.6-27b-4bit)
  версия эталона 3f9c0a1b2d4e, из проверки 98%; слепой контроль: 1 из 28
  пар 336: верно 318, неверно 4, пропущено 3, придумано 1, не размечено 6, нет результата 4
  поле                     верно   неверно  пропущено  придумано  нет рез.  не разм.
  amount_with_vat          51/55   2        2          0          0         1
  …
  разбор: eval/fields-8-20261127-131000.csv
```

### `docreader eval search [--label МЕТКА] [--from ФАЙЛ.json]`

Замер поиска (research R-12), две записи. Модели — как у `docreader search`; без
`--from` на сервере разработки — код 2.

```
Замер поиска: записи 9 (без реранкера) и 10 (с реранкером) «после 02»
  вопросов 64: участвуют 51, без ответа 13, вида «таблица» 0
                 первое место    первые пять    медиана   не найден
  без реранкера  30 / 51 (59%)   38 / 51 (75%)  1         4
  с реранкером   31 / 51 (61%)   48 / 51 (94%)  1         1
  разбор: eval/search-9-10-20261127-133000.csv
```

### `docreader eval results [--stage ЭТАП] [--json]`

Таблица результатов: номер, дата, метка, этап, версия эталона (и «прежняя», если
не текущая), главные метрики.

### `docreader eval show ЗАПИСЬ [--field ПОЛЕ] [--outcome ИСХОД] [--json]`

Метрики записи и случаи по фильтру (SC-004): `D-0012 amount_with_vat неверно`,
`Q-3f9c0a1b2d D-0015 место 7`.

### `docreader eval compare A B [--json]`

Только записи одного этапа (иначе код 1). Разница метрик, затем случаи:
«стало лучше», «стало хуже», «вне сравнения», при разных версиях эталона —
предупреждение и группа «из-за эталона» (research R-13).

### `docreader eval export [--out ФАЙЛ]`

CSV таблицы результатов; печатает путь.

## Вопросы

### `docreader eval questions load ФАЙЛ… [--json]`

```
Вопросы: questions/rerank-08.toml — загружено 28, заменено 0, ошибок 0
Набор: 64 вопроса — текст 64, таблица 0, оба 0; без ответа 13; с ложной посылкой 8
  расходятся признаки у вопросов: 21 (questions/answers-09.toml) и 21 (rerank-08.toml)
```

Предупреждения печатаются, если без ответа меньше 10 или с ложной посылкой меньше 5.

### `docreader eval questions generate [--false-premise N] [--out ФАЙЛ]`

```
Предложенные вопросы: questions/generated-20261127-134000.toml
  с ответом 318, без ответа 16, с ложной посылкой 10 (не хватило пар 0)
  просмотрите файл, уберите лишние и загрузите: docreader eval questions load …
```

### `docreader eval questions clauses --answers ФАЙЛ.json --questions ФАЙЛ.toml [--out ФАЙЛ]`

```
Пункты из ответов: questions/answers-09-clauses-20261127.toml
  вопросов без пункта 8: предложено 8, без подтверждённых утверждений 0
```
