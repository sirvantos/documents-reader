## Summary

Группа подкоманд `docreader eval …` (R-1). Эталон полей собирается **проверкой**:
`eval review` строит локальную страницу, где на каждую пару «документ, поле» шести
полей прототипа — значение фичи 05, значение **правил** (новый `rules.py`: образцы
без модели, каждое значение проходит ту же `verify.check_field`, R-8), цитаты
с картинкой страницы и пометка согласия; аналитик отвечает клавишами, файл ответов
загружается `eval load` (R-9). Поля без предзаполнения и **слепой контроль**
(5 договоров по правилу отбора фичи 05, их карточки скрыты до слепой разметки) —
по пустому CSV-шаблону (R-2, R-10). Загрузка заменяет эталон в пределах охвата
файла, с подтверждением при удалении (R-6); версия эталона — отпечаток содержимого
(R-5). `eval fields` относит каждую пару к одному исходу по таблице R-7 и пишет
запись таблицы результатов со случаями и файл разбора; `eval search` — места
правильных пунктов без реранкера и с ним, теми же вызовами, что замер фичи 08 (R-12).
`eval show`, `compare`, `export` — раскрытие цифры, «лучше/хуже», выгрузка (R-13).
Вопросы загружаются из наборов фич 08 и 09 как есть, **генерируются** из эталона
(с ответом, без ответа, с ложной посылкой) и получают пункты из машиночитаемого
файла ответов замера фичи 09 (R-11). Каталог полей переносится в код с тестом
на совпадение с документом (R-3); новые виды значений — в `values.py` (R-4).
Сравнение, правила и генерация моделей не вызывают; модели нужны только поиску.

## Technical Context

данных: `eval/` (шаблоны, страницы, разборы, выгрузки), `questions/`.

**Testing**: `pytest`, уровень 1 tech-context (модели не участвуют, кроме поиска —
подделки `TopicEmbedder`, `TableReranker`). Модульные — каталог против документа,

CLI на временной базе: синтетические договоры → `extract` (`ScriptedModel`) → `eval
review` → ответы → `eval load` → `eval fields` → `eval compare`; слепой контроль;
вопросы; `eval search` с подделками и `--from`. Уровень 3 не нужен.

**Target Platform**: рабочие прогоны — macOS, Apple M3 Pro, без сети; разработка и
автотесты — Ubuntu 24.04 x86_64 и Docker.

**Project Type**: CLI-приложение, один пакет (как в прежних фичах).

**Performance Goals**: сравнение полей по 56 договорам и 68 полям < 60 с (SC-001; ожидаемо

## Тесты

Модульные (каждый случай — отдельный тест):

- каталог: 68 полей, 35 в очереди 1, 11 вручную; имя, вид, очередь каждого поля
  совпадают с таблицами `docs/field-catalog.md`; `PROTOTYPE` = `fields.PROTOTYPE_FIELDS`;
- новые виды: ИНН 10 цифр с пробелами → цифры; 9 цифр — ошибка; процент «0,1%»,
  «20 %», «20»; число «60 (шестьдесят)»; выбор — регистр и «ё», не из вариантов —
  ошибка со списком;
- CSV: `;` и `,`, BOM и без, строки `#`, ` || `, «Отсутствует», пустая ячейка,
  лишний столбец, нет `document_id`, документ не из реестра; ответы страницы:
  каждый `answer`, неизвестный ключ карточки, `chosen` берёт значение из сборки;
- правило замены: добавлено / изменено / убрано / без изменений в пределах охвата;
  вне охвата не меняется; убирание без `--yes` — ничего не меняется; ошибка вида —
  «не размечено» и в числе убираемых; пара из файла другого вида — названа;
  версия не меняется при той же загрузке дважды;
- исходы: каждая строка таблицы R-7; суммы; доли и знаменатель; сортировка полей;
  неизвлекаемые поля отдельно; наименование без учёта регистра;
- поиск: место первого из нескольких правильных; «не найден»; неучаствующие; медиана
  по найденным; доли;
- сопоставление: «лучше», «хуже» по рангам, «вне сравнения», «из-за эталона», разные
  этапы — ошибка; поиск — место меньше лучше;
- правила: каждое поле на синтетическом договоре; ловушки — номер другого документа
  не берётся за номер договора, сумма штрафа не берётся за цену, дата доверенности —
  не дата окончания; несколько значений — все; без цитаты — не найдено;
- вопросы: ключ стабилен к пробелам и «ё»; наборы фич 08 и 09 загружаются как есть;
  `answers`, `false_premise`, `kind`; ошибки с номером; генерация — каждый вид,
  ложная посылка берёт значение другого договора, не хватает пар — число; подбор
  пунктов из JSON ответов;
- вывод: для каждой команды обычный и `--json` вывод не содержит ни одного значения
  эталона, системы, правил, текста вопроса и цитаты синтетики.

Интеграционные (временная база, `make_extraction_contracts`, `ScriptedModel`):

- история 1: `eval review` — карточки и пометки каждого вида, порядок, слепые скрыты;
  `eval load` ответов — эталон и пути; новое построение переносит ответы; значение
  системы изменилось после проверки — пометка `changed`;
- история 2: `eval template` — 6 / 35 / 68 столбцов; загрузка с ошибкой вида; замена

  `gold_blind`;
- история 3: `eval fields` — по одному случаю каждого исхода; `--source rules`;
  `--from`; файл разбора; запись и случаи; сумма исходов; повтор — те же исходы;
- история 4: `eval results`, `show` по фильтру, `compare` (группы), `export`
  (кириллица, BOM), запись по прежней версии эталона;
